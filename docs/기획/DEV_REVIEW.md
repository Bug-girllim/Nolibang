## 0. 기술 선택의 확정 여부 (서비스 정책과 구분)

- **[기존 확정 기술 선택]** Java·**Spring Boot + JSP**, **MySQL**을 사용한다. 기존 팀 결정에 기록된 **WAR 패키징**과 **`tomcat-embed-jasper` 구성**도 개발 환경의 기준으로 보존한다. 기술 선택이 확정됐다는 것은 프로젝트가 실행·테스트 완료됐다는 뜻이 아니다.
- **[기존 P0 구현 방식]** 초기 9강의·27차시(영상 파일 총수 별도 미확정) 및 카테고리의 데이터는 **SQL 시드 입력 방식**으로 준비한다. [D-01] 신규 세부 취미의 강의·영상 추가도 같은 방식이며 관리자 화면은 검수·승인·상태 전환만 제공한다. 기획·요구사항에는 제공해야 할 콘텐츠 범위만 표기한다.
- **[이미지 기술 방향 채택 / 설정 미확정]** 브라우저 **Canvas API 사전 압축**과 서버의 파일별·전체 요청 제한을 검토 기준으로 사용한다. 압축 수치·제한 설정·실패 처리 테스트는 아직 확정/완료하지 않았다.
- **[기존 결정된 보안·확인 방식]** 비밀번호는 평문 저장하지 않고 적절한 비밀번호 전용 해시를 사용한다. 이메일 재가입 제한 확인에는 **서버 비밀키 HMAC 이메일 확인값을 30일간 보유**한다. 실제 비밀번호 해시 알고리즘·인증 흐름과 이메일 정규화/HMAC 키 관리 방식은 개발 시 확인한다.
- **[구현 후보 / 미확정]** `current_session_id`, `has_pending_report`, 조회 시점 비교, SQL 집계·제약조건, Controller/Service Guard, 세션 쿠키·Heartbeat 주기, 스케줄러/관리자 정리 등은 기술 후보이지 서비스 정책으로 확정한 필드·메서드가 아니다.
- **[현행 MVP 기술 범위]** 신고·관리자 과제 무효·유예·오판 정정은 MVP **화면/API/DB/상태 처리 대상에서 모두 제외**. 현재 관리자는 공개 작품 숨김·복구만(Q-01/Q-02), **수료 확정 후 과제 직접 삭제로 수료 철회시키는 구 D-32 절차는 폐기**, 최종 삭제 후처리는 미정. 수료 철회·배지 유예·무효 후 보완·무효 오판 복구 기술 제안은 **[폐기/이력]**으로 읽고 MVP·확장 구현 대상으로 되살리지 않는다. 신고 관련 상세 기술 제안만 **[확장 참고]**로 둔다.
- **[기획과 개발의 분리]** `PRD` 및 `00~07`에는 사용자 행동·권한·상태·예외 결과를 기록한다. 위 기술 선택과 검증 절차는 이 파일을 기준으로 관리한다.

## 2. 제안 검토 결과 (기술 방식은 권고, 미확정)

### 2-1. 댓글 본문 삭제·탈퇴 익명 처리
- **서비스 확정:** 댓글 **자발 삭제**는 본문을 '삭제된 댓글입니다'로 변경하고 타인 답글 보존. **탈퇴만** 하면 정상 댓글은 본문 식별정보를 비식별 처리한 뒤 원칙적으로 보존·작성자명 익명화(D-25). 둘 다 발생했다면 삭제 본문을 되살리지 않는다.
- **DB 후보:** 댓글 본문 상태와 회원 탈퇴 상태를 분리하고, 탈퇴 시 타인 작품 댓글의 `author_user_id`를 `NULL`로 처리하거나 개인정보가 복원되지 않는 익명 구조로 이관한다. `users.status=WITHDRAWN`만 적용한 뒤 댓글 FK를 원 계정에 그대로 남겨 두는 방식은 기존 '연결 제거' 정책과 **충돌**하므로 채택하지 않는다.
- **[익명화 처리 순서·검증 후보]** 탈퇴 시작 시 계정 이용을 차단하고 → 타인 작품 댓글의 본문 식별정보·맥락상 재식별 위험을 확인하여 마스킹/대체하고 → 댓글/좋아요의 원 계정 참조를 끊거나 안전한 익명 구조로 바꾸고 → 개인 학습·작품·직접 식별 정보를 정리한다. 부모 댓글 자리와 답글은 보존한다. **단순 소프트 삭제(`users.status` 변경)만으로 익명화 완료라고 판정하지 않는다**. DB 트랜잭션·파일 삭제 실패·백업/로그의 식별정보 잔존·관리 화면 접근을 테스트한다(구체적 DB 스키마는 미정).
- [확장 D-33] 신고 증거는 본문 삭제·탈퇴보다 접근 제한된 보존 규칙이 우선할 수 있으며, 공개 댓글 원문을 되살리지는 않는다.

### 2-2. 탈퇴 레코드와 개인정보
- **권장 타협:** `user` 행은 인증 금지·비식별 상태로 남겨 FK 파손 위험을 줄일 수 있다. 그러나 **식별정보와 개인 학습·작품·파일을 실제 제거**해야 하며 댓글/좋아요의 공개 익명 레코드가 이전 사용자 식별자를 계속 보유하면 안 된다.
- 재가입 제한용 이메일은 서버 전용 비밀키 HMAC(정규화 정책 검증), 30일 보존 후 파기 후보. 식별 가능한 닉네임/전화/프로필/로그·백업의 개인정보가 별도로 남지 않는지 확인해야 한다. **모든 개인 데이터가 소프트 딜리트로 자동 파기되는 것은 아니다.** 법적 보유·파기 준수는 별도 검토.
- 구현 후보: 비식별화된 계정 식별자, `withdrawn_at`, 로그인 불가 상태. 실제 필드·컬럼은 DB 설계 때 정한다.

### 2-3. 강사 경고와 인계 (P2)
- **현행 운영 기준:** 최초 제출+168h, 반려 뒤 명시적 정식 재제출+168h만 새 마감 생성. 수정·평가 시작 취소·강사 인계는 기존 기한 그대로. **관리자 공개 작품 숨김/복구는 기한을 면제하거나 재설정하지 않는다(Q-02)**. 과거 관리자 무효 제재를 근거로 한 기한 재설정은 폐기된 규칙이며 적용하지 않는다.
- 관리자 목록은 **지금 시각이 만료를 지난 건(미작성 + 기한 후 작성 완료, D-19)**을 표시하고, 강사별 **만료 KST 날짜**로 묶어 관리자 확인 후 1회 경고. 예: 2026-11-04 18:00(KST) 만료이면 그 시각을 지난 뒤부터 0순위·경고 후보가 된다. 다음 날 자정까지 대기하지 않는다. 11월 4일 안에 다른 제출물이 만료돼도 해당 강사의 11월 4일 묶음에는 경고 1회만.
- **기술 후보:** 조회 시 만료 비교, KST로 변환한 날짜 집계, 경고 이력 중복 방지. 운영 공백은 별도 대기 상태로 보이고 다른 취미/정지 강사에게 공식 피드백을 강제 위임하지 않는다.
- **[D-06] 경고 기록 보존:** 경고 이력은 제출물 FK에 의존하지 않도록 강사·분기·마감 KST 날짜·건수로 저장하는 방식을 후보로 둔다. 같은 제출물 중복 경고 방지는 제출물이 존재하는 동안의 별도 표식으로 처리하고, 제출물 삭제 시 경고 행이 CASCADE로 지워지지 않게 한다.
- **[D-19] 경고 처리 확장:** 피드백 작성 완료 여부와 별도로 **기한을 넘긴 사실/마감 시각**을 추적해야 관리자 확인 전 뒤늦게 작성한 건도 목록에 남는다. 묶음과 분기 귀속 기준은 **강사+마감 KST 날짜/그 마감일의 KST 분기**다. 9/30 마감 10/1 확인은 3분기로 기록하며 조회 시점과 귀속 분기를 혼동하지 않는다.
- **[확장 D-33 · D-03] 신고 중 기한:** 신고 상태는 피드백 기한 계산에 관여하지 않는다. 작성자 탈퇴 등으로 평가 대상의 존속이 달라지는 상황은 별도 검증하되 **관리자 숨김은 면제 사유가 아니다(Q-02)**. 무효 확정에 따른 면제는 폐기된 규칙이다. 승인 완료 과제의 작성자 삭제 후처리는 미정.
- **[D-28] 이미 발생한 지연:** 이미 넘긴 피드백 기한·강사 귀속 분기 정보는 이후 정상 수정·작성자 삭제·탈퇴·인계에도 경고 후보로 유지한다. **관리자 숨김으로 기한 변경 없음**. 저장 기술은 개발에서 결정한다.
- **[Q-04 A]** 이미 공식 피드백이 작성된 과제의 기존 피드백은 **작성자·본문·시간을 유지한 읽기 전용 이력**이다. 새 담당자의 기존 피드백 UPDATE·DELETE 및 2번째 공식 피드백 CREATE를 **화면뿐 아니라 서비스 권한 검사로 거부**한다(실제 DB 제약은 설계 시 결정). 미작성 과제만 인계한다.
- **[Q-05 갱신 · D-52·D-59]** 담당 공백 분반은 **신규 배정에서 제외**하고, 관리자가 분반 담당 강사를 다른 적격 강사로 변경한다. 변경 전까지 기존 확정 수강·영상 완료·수강기간 내 과제 제출은 유지하되 **전문강사의 공식 평가·50자 이상 피드백·수료 승인 전에는 수료되지 않는다**. 마감 시각은 **최초 제출 또는 정식 재제출+168h** 고정이며 이동이 새 마감을 만들지 않는다. 새 담당의 경고 판정은 인계 후 유예 시간 이후(D-43, 수치는 P2 구현 시 결정).
- **[Q-03a B / 안내 방식 A]** 실제 강사 과부하·공백 대상자 안내는 **관리자의 외부 운영용 이메일 수동 업무**로 확정됐다. 서버의 자동 과부하 감지·수신 대상 자동 선정·개별 발송 API/UI·발송 이력 자동화는 현재 MVP 개발 대상이 아니며 확장이다. 정확한 대상·주소 확인, 다른 학습자의 연락처 노출 방지, 피드백 기한·경고 계산과 안내 여부의 독립성을 운영 점검한다.
- **경계 테스트 필요:** 공백 중 신규 제출→**제출 시각+168시간 고정**, 기존 과제 인계→기한 유지, 과거 완료 피드백 수정·재발행 차단, 이미 경고된 제출물의 수정, 정지 후 자동 복귀 금지, 대체 인력 부재 알림.

### 2-4. 문의 신고 진행과 탈퇴 (신고 부분은 확장 D-33 / P2 탈퇴)
- **정책:** MVP는 탈퇴 시 문의 스레드 전체 삭제. [확장 D-33] 탈퇴 시 신고 접수·검토 중인 스레드만 비공개 보존, 그 밖의 문의 스레드는 삭제. 신고 종결 후 법정 보존 사유가 없으면 증거까지 삭제.
- **[확정 정책 D-25 / 구현 방법 검토]** 타인 작품의 익명 댓글 **본문에 개인정보가 남는지**를 원 계정 연결 해제 전에 점검하고 직접 식별 부분은 가린다. 나머지 문장만으로 재식별 가능하면 공개 본문 전체를 삭제·대체하고 답글 구조를 유지한다. 이메일·전화번호의 정규식만으로 모든 개인정보를 제거했다고 주장하지 말고 운영자 점검(이용자 신고는 확장) 경로와 연결한다.
- **[확장 D-33] 기술 후보:** `has_pending_report` 불리언을 둘 수 있으나, 불리언 **단독 진실값으로 믿지 말 것**. 사건 상태와 동기화가 어긋날 수 있으므로 삭제 트랜잭션에서 실제 열린 신고가 존재하는지 검사하거나 한 원천 상태에서 파생 계산한다. 신고 행 FK, 첨부 없는 텍스트 증거, 메시지·보고서 삭제 순서를 함께 검증.

### 2-5. 일반 작품 수준 태그
- 태그 선택 시 **현재 그 취미의 유효 배지 중 가장 높은 수준(유예 제도 폐기)**이 상한. 미보유 취미는 입문만, 고급 배지 회원은 입문/중급/고급 선택. 기존 글은 배지 상실만으로 태그 소급 변경 없음. 강의 등록·수강 수준은 여전히 자유.
- **해석:** 태그 입문은 누구나 댓글 작성 가능하다는 뜻이 아니다. 기존 배지 댓글 권한 그대로(입문 이상 배지 필요, 작성자 본인 답글 예외).

### 2-6. 신고 중 수정과 업로드 [확장 D-33]

> MVP에는 신고가 없으므로 이 절의 신고 잠금은 확장 시 적용한다. 업로드 파일 교체 순서·트랜잭션 원칙은 정상 수정에도 그대로 쓴다.

- JSP의 버튼 비활성은 UI 편의일 뿐 권한 검사 아님. Controller를 거친 뒤 Service에서 **DB 최신 신고 상태를 재조회**하고 수정·삭제를 거부. 검증 실패 시 정상 파일을 교체·삭제하지 않는다.
- **주의:** Multipart 요청이 서버에 전송되거나 임시 저장되는 것을 Guard 하나로 원천 차단할 수는 없다. **영구 저장/기존 파일 교체를 막는 것**이 현실적인 표현이다.
- **동시성 한계:** 상태 검사 → 파일 저장 사이에 신고가 새로 시작하는 경쟁 상태가 생길 수 있다. 확장 도입 시에는 저장 직전 재검사와 DB 변경을 한 트랜잭션에 묶는 방식을 검토한다. 단순 최초 Guard만으로 **완전한 잠금 보장이라고 주장하지 않는다**.
- **[확장 D-33 · D-24 / 구현 방법 검토]** 신고를 1건씩 독립 잠금으로 보지 말고 **대상(작품·댓글·피드백·문의 등)별 진행 중 검토 사건**에 동일 사유 신고 접수 내역을 연결하는 데이터 모델을 검토한다. 기존 사건의 최초 접수 시각·권고 처리 기한과 수정 잠금은 재시작하지 않는다. 진행 중 동일 사유의 새 증거는 기존 사건에 추가한다. 종결된 동종 사건의 재접수는 새로운 근거 확인 전 자동 재잠금하지 않는다. **종결 후** 새로운 근거나 다른 사유·변경된 대상은 관리자 판단에 따른 신규 신고 검토 대상이다.

### 2-7. 영상 시청 시간·세션은 다른 Heartbeat
- 영상 재생 중 약 **5초 단위 진행 Ping 후보**, 서버에 마지막 요청 시각과 신뢰할 수 있는 누적 실제 재생 시간을 보존. 이전 정상 진행 Ping 이후의 **서버 관측 경과시간을 상한**으로 누적(중복·급격한 증가·일시정지·백그라운드/비재생 상태를 검증).
- 벽시계 재생 시간 규칙 유지: 배속 2배이면 5초 재생에 약 5초만 적립. 반복/되감기는 실제 재생 시간 추가, 스킵 점프 자체는 미적립.
- Ping만으로 사용자 실제 시청을 **증명할 수 없으며** 위조된 재생 상태도 조작 가능하다. 외부 DRM 없는 현실적인 남용 억제 수준으로 평가한다. 전송 횟수·일시중단/재생 복귀·탭 비활성·중복 요청을 테스트.
- **[회의 보드 위험 검토안 · §3-2]** 빠른 탐색(스킵), 배속, 중복 탭, 연속 Ping, 일시정지 상황을 구현 초기부터 시뮬레이션한다. 실제 재생을 완벽히 증명할 수는 없으므로 서버 관측 시간의 상한·중복 적립 방지 등 수용 가능한 검증 수준을 기록한다.
- **인증/세션 하트비트는 분리:** 기본 유휴 60분, 재생 중 연장, 일시정지 시작부터 2시간 연장 뒤에는 연장 중단하고 마지막 요청 기준 유휴 60분을 적용. 웹페이지의 단순 Ping만으로 사용자의 일시정지 시작 시각을 식별하지 못하면 2시간 상한을 적용할 수 없으므로 **서버가 검증 가능한 시작 시각·상태**가 필요. **구현 후보(미확정):** `lastPausedAt`(일시정지 시작), `accumulatedWatchSeconds`(신뢰된 실제 재생 누적), `lastPingAt`(마지막 정상 재생 Ping) 같은 값을 세션/서버 저장소에 분리 기록하고 서비스 로직·인터셉터에서 판정한다. **세 필드명·저장 위치·스레드/타이머 구성 자체는 필수가 아니며**, 실제 재생 누적과 로그인 연장 상태가 독립적으로 동작하는 것이 검증 기준이다.

### 2-8. [폐기 이력] 관리자 무효 14일·30일 처리 — 현행 DB·API 제외
- 배지 권한과 30일 비공개/정정 가능 여부의 **판정**은 화면 요청 시 현재 시각과 비교하여 즉시 계산하는 방식을 추천(스케줄러 없어도 경계 검증 가능).
- **반드시 분리:** 목록 필터와 `now()` 비교는 **실제 사진/DB 행 삭제를 실행하지 않는다**. 수동 관리자 정리 버튼은 시연 방법이나 운영 편의로 가능하지만 **30일 후 자동 물리 삭제 정책의 완전 이행은 아니다**. 실제 준수/운영은 삭제 실행 방식(작업·스케줄러·관리자 정기 조치)과 실패 재시도·감사 확인이 필요.
- [D-07 확정] 30일 보관 = **무효 확정 시각 + 30×24시간**(오판 정정 가능 기간 동일). 탈퇴 재가입 확인값 = 탈퇴 시각 + 30×24시간, 종료 공지 = 종료 시각 − 30×24시간. 모든 기준 시각은 UTC 또는 KST 중 하나로 통일해 저장하고 표시만 KST로 변환하는 방식을 권장한다. 남은 것은 예외 보존 근거와 실제 파기 실행 설계다.

### 2-9. 입력 원본 50MB × 최대 5장 — 압축/업로드 설계
- **기획 정책(확정, `05-policy.md`):** 사용자가 선택한 입력 원본 이미지는 **1~5장, 장당 최대 50MB**. 한 장이라도 업로드·등록 실패 시 최종 제출·수료는 미완료다. **압축 후 용량을 이 기획 상한과 혼동하지 않는다.**
- **개발 설계 방향(채택, 구현·검증 전):** 입력 원본의 개수·크기를 먼저 확인하고, 지원되는 이미지에 대해 **브라우저 Canvas API 기반 디코딩·리사이즈·압축**을 거친 뒤 전송한다. 서버는 **개별 업로드 파일 크기와 전체 multipart 요청 크기를 별도로 제한**하고, 파일 유형 및 실제 이미지 유효성을 검증한다. 구체적인 전송 상한·해상도·압축 품질은 개발 설계/테스트에서 정한다.
- **[회의 보드 후보 / 설계 미확정]** P0 우선 구현안은 Canvas 사전 압축에 의존하지 않고 1~5장·원본 장당 최대 50MB를 검증해 전송하는 것이다. 예를 들어 Spring Boot의 `spring.servlet.multipart.max-file-size`는 **개별 전송 파일의 상한**, `spring.servlet.multipart.max-request-size`는 **파일·폼 필드를 모두 포함한 전체 multipart 요청 상한**으로 구분해서 설정·테스트한다. **5×50MB에 딱 맞춘 전체 250MB만으로는 multipart 오버헤드 때문에 정상 최대 업로드가 실패할 수 있으므로**, 실제 테스트에 맞는 여유 상한을 설정하고 Tomcat/프록시/저장소/타임아웃·임시 파일 용량·업로드 남용을 별도로 확인한다. 서버 전송 제한은 사용자 입력 원본 상한과 다른 개념이다. 임시 파일 정리·DB 기록 확정·부분 실패 복구를 검증해야 한다. **설정값과 이 방식의 채택·구현·테스트 완료는 아직 미확정**이다.
- **실패 처리:** 원본 한도 초과, 브라우저 압축 실패, 압축해도 서버 전송 제한 초과, 네트워크 오류, 서버 검증 실패 시 실패 사유를 안내하고 성공으로 기록하지 않는다. 압축 실패 시 무검증 원본을 자동으로 우회 전송하지 않는다. 서버 저장/DB 등록이 모두 성공해야 완료로 확정한다.
- **주의·검증:** 고해상도 이미지는 Canvas 디코딩 중 브라우저 메모리 부족이나 방향·투명도/파일 형식 변화가 생길 수 있다. 원본 50MB를 항상 특정 크기로 줄일 수 있다고 보장하지 않는다. 파일 MIME·확장자·실제 디코딩, 접근 권한, 이전 파일 교체·정리 순서를 검증한다.
- **[원본 크기 검증의 신뢰 경계]** Canvas로 압축한 **전송본만 받는 서버는 압축 전 원본 파일 크기를 해당 전송 바이트만으로 재검증할 수 없다**. 브라우저의 원본 `File.size` 검사는 정상 UX를 위한 필수 점검 후보지만, 임의 HTTP 요청은 이 검사를 우회할 수 있다. MVP 원본 전송 방식의 서버 상한 검증과, 추후 Canvas 채택 시 정책 준수 증명·서버 자체 전송 제한·악용 대응 방식을 구분해서 설계·테스트한다. 이 한계를 해결하지 않은 채 “서버가 압축 전 원본 50MB를 보장한다”고 단정하지 않는다.
- **[D-22] 일반 작품도 같은 입력 검증 적용**: JPG/PNG/WebP, 원본 1~5장·장당 최대 50MB·전체 성공 시에만 등록 완료. 일반 작품 실패는 수료 상태 변경 없이 반환한다.
- **경계 원칙:** 이미지 업로드 기술은 이 문서에서만 상세화한다. `PRD`/`02~05`에는 사용자가 업로드할 수 있는 조건과 실패했을 때의 서비스 결과만 기록한다.

### 2-10. 과제 평가 시작·반려·수료 승인·배지 중복 방지 (P0)
- UI의 제출 중 비활성화/로딩 표시는 이중 요청 감소용일 뿐 서버 보장을 대신하지 않는다.
- **DB 후보 검토 수정 [2026-11-05 D-55 갱신]:** 같은 강의 재신청 불가로 **`(user_id, lecture_id)` 영구 UNIQUE 제약을 그대로 사용**한다(재신청 허용 시 재검토). 최종 제출물은 **수강 회차당 동시 평가 대기 1건**, 수료/배지 중복 발급, 정원/자동 확정 동시 요청, 멱등성을 각각 검증한다. 특정 DB 제약·인덱스는 미확정이다.
- **[회의 보드 후보 / 설계 미확정]** 수강은 학습자·강의에 **회차를 더해 구별**하고 활성 신청/대기 상태의 중복만 제한한다. 수료는 **수강 회차별 승인 이력**, 배지는 취미·수준별 인정 수료 1건 이상으로 검토한다. 배지는 취미별 독립이므로 취미를 빠뜨리면 안 된다. 특정 DB UNIQUE 인덱스·컬럼명·과거 수료 이력 모델은 ERD 설계에서 결정한다. DB 트랜잭션과 외부 파일 저장은 동일한 원자적 작업이 아니므로 실패 파일 정리·재시도가 따로 필요하다.
- **[복수 동일 수준 강의 검증]** 취미/수준 배지 조건은 **그 취미·수준에서 강사 승인된 인정 수료 1건 이상**이다. A 수료 후 B가 수강 중/미수료여도 A 배지는 유지한다. **승인 완료 과제 직접 삭제에 따른 배지 변경은 현행 수료 철회 제도 폐기로 미정**이므로 A 삭제 시 배지 철회 테스트를 확정하지 않는다. 초기 9강의 증설 결정이 아니라 데이터 확장 시 참고하는 경계 검토다.
- **[D-16 폐기]** 관리자 무효 판정의 과거 A/B 오판 복구 설계는 폐기한다. 강사의 반려를 수료 승인으로 정정하는 절차는 **[확장 D-37]**이며 MVP 상태 전이에 포함하지 않는다.
- **제출 단계** 파일 검증·등록 성공 → **평가 대기(미수료)**를 일관되게 저장한다. 이후 별도 **강사의 최소 50자 피드백+수료 승인**이 성공할 때만 수료·배지를 일관되게 갱신한다. 업로드 실패·동시 승인 중복과 고아 파일 정리를 검증한다.

### 2-11. 한 계정 한 활성 세션·일시정지 제한 (P1)
- **정책:** 동일 계정의 다른 기기 새 로그인 시 기존 로그인 세션 거부. 일반 유휴 60분, 영상 재생·일시정지 중 연장, 일시정지 시작 후 최대 2시간 연장.
- **후보 구현:** 서버에서 계정별 최신 활성 세션 식별자를 비교하는 방식(`current_session_id` 또는 안전한 대체키·해시 참조). 기존 세션은 **다음 인증 요청에서** 종료됨을 우선 검증하고, 원격 기기에 즉시 화면이 바뀌는 것으로 과장하지 않는다. ID 저장·전송의 세션 하이재킹 위험을 줄이고 로그인 시 갱신 동시성·로그아웃·재시작도 점검.
- 무조건 5분마다 빈 `/api/ping` 호출만 하면 **일시정지 2시간 초과 후에도 연장이 계속되어 정책 위반**이다. 서버가 마지막 재생/일시정지 시작을 기준으로 핑 허용을 제한해야 한다.
- Redis 없는 단일 서버의 인메모리 세션은 서버 재시작 시 로그아웃될 수 있다. 학습 앱에서 허용 가능한지 테스트로 표시.

### 2-12. 강사 임시 비밀번호 즉시 생성 (D-51, P0 · 구 D-10 설정 링크 대체)

- **[현행 D-51]** 관리자가 아이디·실명·이메일로 계정을 만들면 서버가 임시 비밀번호를 생성해 화면에 1회만 보여 주고 `password_hash`(임시 비밀번호의 해시)와 `must_change_password = true`로 **즉시 활성** 저장한다. 첫 로그인 성공 시 비밀번호 변경 화면 외 요청을 서버에서 막고, 변경 완료 시 플래그를 해제한다. 재발급도 같은 방식. 이메일 발송·토큰·SMTP 의존이 사라져 FR-012 완료 기준에서 메일 수신 검증을 제외한다. 임시 비밀번호는 화면에 한 번만 보여 주고 로그·DB에 평문으로 남기지 않는다.
- **[이력 · 아래는 구 D-10 설계]**
- 관리자가 강사 계정을 만들면 비밀번호 미설정 상태로 저장하고, 비밀번호 재설정(FR-004)과 같은 일회용 토큰 링크를 강사 이메일로 보낸다. 토큰은 해시로 저장하고 만료 시간을 둔다(값은 개발 시 결정), 사용 후 즉시 폐기.
- FR-004(P1) 재설정 흐름보다 먼저 필요하므로 **토큰 발급·검증 모듈은 P0 이메일 인증과 공용으로 만든다**. 이메일 발송·수신이 막힌 경우 **관리자 화면에 비밀번호 설정 토큰·링크를 노출하는 방식으로 우회하지 않는다**. 실제 이메일 전달이 되지 않으면 FR-012의 완료 기준은 미충족으로 기록하고 발송 환경을 우선 해결한다.

- **[회의 보드 후보 / 설계 미확정]** 가입 인증·전문 강사의 최초 비밀번호 설정·이후 계정 복구는 목적별 만료·일회성 사용 규칙을 공유하는 토큰 처리로 통합하는 방안을 검토한다. 이메일 발송·수신 및 목적별 상호 사용 불가를 테스트해야 한다. 실제 SMTP 환경이 마련되지 않았으면 해당 인증 기능을 완료로 주장하지 않는다.

### 2-13. 시연용 시드 데이터 (P0)
- 배지 기반 댓글 권한 때문에 빈 서비스에서는 댓글을 쓸 사람이 없다. 시연용으로 **수준 배지·마스터 배지 보유 학습자, 배지 없는 학습자, 강사 2명(같은 취미), 관리자** 계정과 공개 작품·댓글 몇 건을 시드로 준비한다.
- 시드 계정의 수료·배지도 실제 제출 흐름과 같은 상태값을 사용해야 권한 테스트가 의미 있다.

- **[회의 보드 후보 / 구현 검증 전]** 짧은 시연용 영상 9개를 SQL 시드로 준비하는 방법은 콘텐츠 준비 부담을 낮춘다. 다만 승인 상태를 시드에 직접 지정하는 것은 **관리자 검수·공개 승인 화면(FR-014)을 구현했다는 근거가 아니다**. FR-014(P1) 구현 완료 여부는 별도 화면·권한 검증으로 판정한다.

### 2-14. 성장 기록 강화 (D-12~D-14, P1)
- **회고 안내문(D-14):** 입력 placeholder 문구 변경뿐, 데이터 변경 없음.
- **첫/최근 썸네일(D-13):** 기존 작품 데이터에서 본인·선택 취미·유효(무효·삭제 제외) 조건으로 최초 등록일 최소·최대 1건씩 조회. 수정일이 아니라 등록(유효 제출)일 컬럼을 기준으로 해야 정상 수정 시 순서가 흔들리지 않는다. 썸네일은 첫 번째 이미지를 사용하는 방식을 후보로 둔다.
- **최근 피드백 연결(D-17 / D-12 / D-47):** 일반 작품 등록 시 본인·같은 취미의 유효 공식 피드백(**수료 승인 피드백 또는 반려 사유**) 최신 1건을 표시한다. 선택하고 저장하면 **작품↔피드백 참조 관계를 실제로 저장**하며 성장 타임라인에서 참조를 조회한다. 선택하지 않으면 참조는 없다. 타인 피드백 연결 및 숨김 피드백의 원문 조회를 서버에서 차단하고, **[확장 D-33] 피드백 자체가 신고에 의해 숨김 처리된 경우에만** 참조 유지·원문 비노출, 관리자 승인 시 재노출한다. 과제 무효 연동(D-30)은 **폐기**. **[MVP Q-02] 관리자 작품 공개 숨김만으로 작성자의 원본 공식 피드백 열람은 차단하지 않는다.** 일반 작품 삭제 시에는 해당 작품의 **참고 연결만 제거**하고 원본 피드백은 유지한다. 재수강으로 보관하지 않은 이전 회차 반려 사유가 삭제되면 참조도 해제한다(D-44). **컬럼·FK·삭제 정책은 DB 설계에서 결정**하되 체크박스만 저장 없이 표시하는 구현은 요구사항을 충족하지 않는다.

### 2-15. 작품 삭제 (D-32)
> **[구 기술안/폐기]** 제출 즉시 자동 수료, 본인 삭제→수료 철회→재수료 순환은 2026-10-30 PDF에 따라 더 이상 실행할 흐름이 아니다. 승인 후 직접 삭제의 후속 결과는 미정이다. 정식 공개 전 외부 성취 증빙 캡처와 실제 자격 불일치, 반복 업로드에 따른 운영비·이력의 신뢰성, 동시 삭제·재제출 멱등성을 `00-backlog.md` PUB-SEC-10에 따라 검토한다.

- **[폐기된 구안]** 최종 과제 삭제→수료 철회→배지 재판정 트랜잭션은 구현하지 않는다. 일반 작품 삭제만 기존 등급대로 적용하고, 수료 승인 과제 삭제·관련 참조·피드백 처리는 **추가 정책 결정 후** 안전하게 설계한다.
- 이미 넘긴 피드백 기한의 지연 기록(D-28)은 학습자 삭제로 지우지 않는다. [확장] 무효 확정 후 30일 보관 중인 과제는 학습자 삭제 대상이 아니다.
- 삭제 후에도 영상 60% 완료 기록은 남으므로 새 최종 과제 제출 → 재수료 경로가 열려야 한다.

### Q-04~Q-06 구현 검증 계약 (기존 스택·FR 등급 그대로)

- **Q-04:** 작성된 공식 피드백은 교체 전후 강사·시간·본문 동일. 이전/새 담당자 모두 기존 작성 피드백 수정 거절. 신규 담당은 **미작성 건만** 작성 가능(숨김 최종 과제의 현 담당 열람은 Q-02대로 허용).
- **Q-05 현행(11-05 갱신):** 담당 공백 분반에는 **새 신청을 배정하지 않는다**(D-52). 기존 수강자의 영상 진도·30일 내 과제 제출은 계속 가능하나 자동 수료되지 않는다. 미평가 제출은 평가 대기이며 분반 담당 변경(D-59) 후 승인된다. 최초 제출/정식 재제출 시각+7일 마감을 담당 여부와 무관하게 고정, 경고 이력 보존. 1:1 새 문의는 공백 동안 제한.
- **Q-06:** 피드백 제출 → 학습자 알림 1건 → 알림함 조회·상세 링크 확인(P0). 댓글·문의(P1) 미구현 시 그 알림 부재가 FR-035 P0 실패는 아님; 해당 기능 구현 후에는 이벤트 누락 테스트. 신고 피드백 재공개 알림은 MVP에서 생성하지 않음.

### 사용자 시연 경로 — 단계별 독립 검증

1. **계정**: 사용자 이메일 인증·로그인(강사는 임시 비밀번호 첫 로그인 변경 확인).
2. **강의**: 운영 중 취미·9강의 확인, 자유 수강 신청.
3. **진도**: 60% 실제 재생 완료 및 스킵·배속·일시정지 예외.
4. **제출**: 이미지 1~5장·원본 50MB 이내 업로드, 일부 실패 시 수료 미발생.
5. **수료**: 중복 없이 수준 배지 및 학습 현황 생성.
6. **강사 피드백**: 현재 담당 강사만 비공개 제출물 접근, 공식 피드백 50자 이상, 학습자 알림.
7. **성장 기록**: 최종 과제·일반 작품과 회고·선택 참고 피드백 연결을 확인하는 것이 **현행 FR-027/028 전체 검수**. 최종 과제만 표시하는 축약형은 부분 시연으로 구별.

**작업 순서 후보:** 데이터 관계·인증 토큰 검증 → 진도·이미지 업로드 위험 확인 → 신청·수료·배지 → 공식 피드백·알림 → 성장 기록 → 커뮤니티 등 나머지 기능. 개발 순서 제안일 뿐 **FR 우선순위 변경이나 기능 제외 결정이 아니다**. 보안·접근 제어 테스트는 모든 단계에 포함한다.

**열린 개발 검증:** I-03 토큰 공용화, I-08 성장 기록 중요도, I-09 실제 물리 삭제와 조회 만료 분리(확장은 별도), I-10 Ping 한계, I-11 세션 연장 상한, I-12 업로드 한도·브라우저 메모리, I-13 기존 댓글·좋아요 보존 정책 아래 이미지 교체·정리, I-15 ERD 확정. 임의로 확정 정책으로 올리지 않는다.

## 4. 실제 개발 착수 전 빠른 검증 시나리오

1. 이미지 1~5장 업로드: 50MB 원본 수용·압축 실패·일부 실패·([확장] 신고 검토 중 오래된 폼 전송).
2. 동일 수강 신청/제출 버튼 연타 및 두 요청 동시 실행: 수강·유효 제출·수료·배지 한 번만 생성.
3. 10분 영상: 6분 실제 재생 뒤 완료, 2배속/되감기/일시정지/스킵/짧은 연속 Ping 악용 테스트.
4. 만료 2026-11-04 18:00 KST: 직전에는 경고 금지, 직후 0순위, 같은 강사·같은 날 두 건이어도 관리자 경고 한 번.
5. 기존 P2 경고에 따른 강사 정지 → 적격 강사 부재/관리자 공백 안내 → 새 강사 배정 → **기존 최초 제출·정식 재제출 기준 7일 기한 그대로 승계** → 이미 발생한 지연/경고 이력 보존.
6. 일반 작품 미수강 취미 입문 등록, 중급 배지 없는데 중급 선택 거절, 기존 태그/댓글 권한 독립 재판정.
7. 댓글 직접 삭제 후 탈퇴: 본문 복원 금지·답글 유지. 정상 댓글 탈퇴(D-25): 본문 개인정보 마스킹·필요 시 전체 대체, 탈퇴 표시명, 원 계정 연결 제거.
8. [확장 D-33] 신고 중인 1:1 문의 상태로 탈퇴: 해당 문의만 보존 후 종료 시 삭제, 비신고 문의 즉시 삭제.
9. **[폐기]** 관리자 무효→수료 철회·14일 유예·30일 자료 보관 관련 만료/파기 테스트는 현행 대상에서 제외한다.
10. **[폐기]** 고급 배지 무효→마스터 유예/철회→재수료 복구는 현행 정책 아님. 평가 승인에 따른 배지 발급을 검증한다.
11. [확장 D-33] 강사가 담당 비공개 과제를 신고하더라도 신고 접수 자체로 기존 7일 평가 기한은 재설정되지 않는다. **관리자 무효에 따른 면제·철회는 폐기**됐으며 신고 이후 세부 운영은 확장 회의에서 결정한다.
12. 경고 받은 제출물의 학습자 탈퇴 후에도 강사 분기 경고 횟수 유지.
13. 강사 계정 생성(임시 비밀번호) → 즉시 로그인 가능 → 첫 로그인 시 변경 화면 외 접근 거부 → 변경 후 담당 강의 확인 → 관리자 재발급 시 다시 변경 강제.
14. 성장 기록: 같은 취미 작품 3개 중 첫 작품 정상 수정 후 순서 유지, **작성자 본인 삭제(D-32) 후 목록·요약 제외**, 다른 취미 선택 시 요약 전환. **관리자 무효·신고 피드백 숨김은 확장**.
15. [확장 D-33 · D-24] 서로 다른 사람이 같은 작품·사유로 진행 중 신고 3회 → 관리자 사건은 1개, 최초 접수 기한/수정 잠금 재시작 없음. 종결 후 근거 없는 재신고는 자동 잠금하지 않음. 진행 중 새 증거는 기존 사건에 첨부.
16. [D-25] 탈퇴자가 타인 작품에 남긴 댓글에 이메일·전화번호 포함 → 원 계정 연결 해제 전 마스킹. 맥락으로 재식별 가능할 때 본문 대체·답글 유지. 자발 삭제 댓글 복원 금지, ([확장] 진행 중 신고 증거 비공개 제한 보존).
17. [D-28·현행] 최초 제출/정식 재제출의 고정 마감을 초과한 뒤 학습자가 수정해도 **수정만으로 새 기한이 생기지 않는다**. 재배정·평가 시작 취소도 동일. 이미 발생한 지연/경고 이력을 소급 삭제하지 않는다. 탈퇴로 과제가 삭제되는 경우의 책임 정리는 별도 검증한다.
18. **[폐기 이력 D-30]** 관리자 과제 무효→수료 철회→A/B 재수료/무효 오판 정정 테스트는 현재 MVP·확장 모두에서 제외한다. 강사 반려 오판 정정은 별개이며 **[확장 D-37]**이므로 MVP 테스트에 넣지 않는다.
19. [D-29·D-31] 준비 중 취미로 일반 작품 등록 거부, 담당 공백 강의의 1:1 작성 차단, 알림 대상 외 이벤트 미알림, 최종 과제 제목 수정 후 검색 반영.
20. [D-32 현행] 일반 작품 작성자 직접 삭제 검증(P2). 수료 확정된 최종 과제의 직접 삭제·관련 참조/피드백 보존·배지 영향은 **미정**으로, 기존 즉시 철회 및 재수료 흐름을 검증하지 않는다.
21. [MVP] **신고 UI·API 및 관리자 무효 처리 UI·API 미구현**; 관리자 공개 작품 숨김·복구만 검증한다. 숨김 중 작성자/담당 강사 열람·수료/피드백 의무 유지(Q-01/Q-02).

22. [회의 보드·진도] 스킵·배속·동일 계정 다중 탭 재생 시 실제 관측 경과시간 초과 누적 방지, 일시정지 중 Ping 무적립 확인.
23. [회의 보드·업로드] 원본 장당 50MB·최대 5장 수용 및 한도 초과 거부, 요청 크기 제한/타임아웃/부분 실패 후 고아 파일 정리 확인. Canvas 없이 처리하는 방식은 검증 후 채택.
24. [회의 보드·권한] 다른 학습자·미배정 강사·비회원이 이미지 원본에 직접 접근하지 못하며, **관리자 숨김 최종 과제는 작성자·현재 담당 강사만 계속 열람** 가능한지 확인.
25. [인증] 가입 인증 토큰은 만료·사용 완료 후 재사용 불가. 강사 계정은 토큰을 쓰지 않고 임시 비밀번호로 생성(D-51).
26. [회의 보드·시연] 제외 기능은 미구현 상태로 표시되며, 최종 과제만으로 타임라인을 보여 주는 부분 시연을 FR-028 전체 구현이라고 오인하지 않도록 확인.

27. **[FR-035/036·조치 알림]** 관리자가 공개 최종 과제/일반 작품을 숨김·복구 → 작성자 U-S16 사유 확인. 작성자에게 **사이트 알림** 생성 확인(이메일 없음, D-57); 신고·무효·정정 통지는 MVP에 없음.
28. **[D-17/D-32·참조 무결성]** 일반 작품 X가 피드백 F를 참고하고 있을 때 X를 삭제 → X 댓글·좋아요·피드백 참조만 정리, F와 원 최종 과제 유지. **승인된 최종 과제 삭제 시 F 원본·X의 참조·배지의 후처리는 미정**이므로 삭제·철회 테스트에 넣지 않는다.
29. **[배지 복수 강의 경계·후속 데이터]** 같은 취미/수준 A 승인 수료→B 미수료인 경우 기존 배지 유지, 세 수준 수료 시 마스터 배지 인정. **수료 확정 과제 A 삭제에 따른 배지 철회는 미정**이므로 검증 기준으로 단정하지 않는다. 초기 강의 증설 요구가 아니다.
30. **[D-32·출시 전 위험]** 수료 승인 과제 삭제→재제출 반복은 **폐기된 수료 철회 시나리오와 연결된 구 악용 가정**이다. 현행으로 구현하거나 정답 테스트하지 않으며, 승인 과제 삭제 가능 조건을 먼저 결정한다. 자료 삭제/보존의 보안 위험은 PUB-SEC-10에서 별도 검토한다.
31. **[D-52·FR-052]** 대기자 1명 이상인 강의에 빈자리가 생긴 상태에서 신규 신청 → 즉시 확정되지 않고 대기열 끝으로 진입. 담당 공백 분반에는 배정되지 않음. 여러 분반 여유 시 **남은 자리가 가장 큰 분반**(같으면 분반 번호순)이 선택됨. 강사 합산 30건은 검사하지 않음.
32. **[D-53·D-54·FR-053]** 수료 승인·수강 취소·만료 반환 → 같은 트랜잭션에서 대기 1순위가 수강 확정되고 사이트 알림 생성. 동시 반환 2건이면 1·2순위가 각각 1건씩 확정(중복·정원 초과 없음). 대기자는 확정 전 대기 취소 가능, 재신청은 끝순번.
33. **[D-35·D-55·FR-055]** 수료·취소·만료한 강의에 신청·대기 → 거부와 안내 문구.
34. **[D-58·FR-051]** 강사 통계의 분반별 수강 중·수료·반려·평가 대기 수가 현재 상태와 일치. 다른 강사·학습자 접근 거부.
35. **[D-59·D-43]** 분반 담당 변경 → 진행 중 초안·잠금·7일 마감 승계, 원 담당 쓰기 거부, 정원 변화 없음. 인계 후 유예 시간 안에 처리된 건은 새 담당 경고 대상 아님.
36. **[D-42·D-41]** 미수료 만료 회차의 영상 재생 거부·수료자 재생 허용. 확정 후 23일 경과 시 제출 화면 안내 노출.
31. **[재생/업로드 신뢰 경계]** 영상 Ping을 반복하거나 클라이언트 시간을 조작해도 서버 관측 상한을 초과 적립하지 않는지, 재생 시간 누적과 로그인 연장 시각이 독립인지 검증한다. 파일 5개가 각 50MB에 가까운 최대 multipart 요청·오버헤드·부분 실패를 테스트한다. 압축본만 서버로 받는 경우 **압축 전 원본 용량을 서버가 독립 검증했다고 주장하지 않는다**.
