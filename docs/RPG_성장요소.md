# RPG 성장 요소 (캐릭터·퀘스트·보스전·직업·꾸미기·길드)

> 작성: 2026-11-11 · 브랜치 `feature/rpg-growth` · 화면: `/my/character`, `/my/guild` (학습자 전용)

## 1. 설계 원칙

- **경험치·레벨·직업·길드 순위는 저장하지 않고 기존 기록에서 계산한다.** 기존 서비스에 "점수 지급" 코드를 끼워 넣지 않아도 되고, 기록과 점수가 어긋나지 않는다. 규칙은 `GameRules` 한 파일에 모았다.
- **새로 저장하는 것은 네 가지뿐이다.** 퀘스트 보상 수령(`quest_claims`), 꾸미기 장착(`user_avatars`), 업적 배지 획득 기록(`user_achievements`), 대표 배지 장착(`user_equipped_badges`). 아이템·퀘스트 목록은 코드(`AvatarItem`, `QuestType` enum)로 정의한다.
- 새 도메인 `game`을 추가했다(CONVENTIONS §1 도메인 목록 외 — 팀 합의 필요). 다른 도메인 데이터는 `BadgeService`(C12)·`HobbyService`·`MyLearningService`를 통해서만 읽고, 여러 표를 한 번에 세는 쿼리는 `GameStatQuery`(`InstructorStatQuery`와 같은 방식)로 둔다.

## 2. 기능 ↔ 구현

| 요소 | 구현 |
|---|---|
| 캐릭터·레벨 | 총 경험치 → 레벨(누적 50×L×(L−1)), 칭호(새싹 놀이꾼 → 견습생 → 수련생 → 숙련가 → 장인) |
| 직업·스킬 트리 | 취미별로 수료 배지(`BadgeService.getBadges`)에서 계산: 견습생 → 숙련자 → 고수 → 마스터 |
| 보스전 | 수강 1건 = 보스 1마리. `MyLearningService`의 상태(학습 중·평가 대기·평가 중·반려·수료·만료)를 보스 체력·문구로 변환. 과제·결과 화면에도 문구 추가 |
| 퀘스트 | 일일 3개·주간 4개. 진행도는 기록에서 세고, 받은 기록만 `quest_claims`에 남긴다(기본키 = 같은 기간 중복 수령 방지) |
| 꾸미기 | 캐릭터 아이콘·테두리·닉네임 색. 해금 조건(레벨·마스터 배지)을 만족한 것이 "인벤토리". 장착은 서버가 해금 여부를 다시 확인 |
| 업적 배지 | 15종(학습 6·작품·소통 5·성장 4)을 `AchievementType` enum 으로 정의. 달성 여부는 활동 기록에서 계산하고, **받은 기록(획득 날짜)만 `user_achievements`에 저장**. 아이콘은 이모지. 알림은 보내지 않고, 처음 받은 화면에서 NEW 표시 |
| 수료 배지 | 기존 `BadgeService`(입문 🥉·중급 🥈·고급 🥇·마스터 👑)를 같은 화면에 함께 표시 |
| 대표 배지 장착 | 받은 업적 배지·수료 배지를 **최대 3개** 장착해 캐릭터 카드에 표시. `user_equipped_badges`(칸 번호 1~3)에 저장하고, 가진 배지인지는 장착할 때 서버가 다시 확인. 수료 배지 코드는 `C{취미 id}-{B·I·A·M}` |
| 길드 | 분반 = 길드, 담당 강사 = 길드마스터. 점수 = **그 분반에서 쌓은 기여 경험치**(차시·과제 제출·수료). 총 경험치를 쓰면 여러 강의를 듣는 사람이 모든 길드에 중복 합산됨 |

## 3. 경험치 규칙 (`GameRules`)

| 활동 | XP |
|---|---|
| 차시 완료 | 30 |
| 최종 과제 제출(재제출 포함) | 50 |
| 보스 격파(수료) | 100 + 100×수준(입문 1·중급 2·고급 3) |
| 공개 일반 작품 | 40 |
| 댓글 | 5 (경험치 반영 최대 20개) |
| 내 작품이 받은 좋아요 | 3 (최대 100개) |
| 퀘스트 보상 | 퀘스트별 10~80 |

## 4. DB 변경 (로컬 MySQL에 직접 적용)

`src/main/resources/sql/migration_game.sql` — `CREATE TABLE IF NOT EXISTS`라서 여러 번 실행해도 안전하다. 내용은 `schema.sql` 맨 끝에도 같다.
`ddl-auto: none`이라 **표가 없으면 `/my/character`가 SQL 오류**로 실패한다(`withdrawn_at`과 같은 상황). 공용 DB를 쓰는 팀원은 이 SQL을 적용해야 한다.

```bash
mysql -u wanted -p --default-character-set=utf8mb4 nolibang < src/main/resources/sql/migration_game.sql
```

## 5. 업적 배지 동작 방식

- **내 캐릭터 화면을 열 때** 달성 여부를 계산해서 새로 달성한 배지를 저장한다(기존 서비스에 배지 지급 코드를 끼우지 않으려는 선택). 그래서 획득 날짜는 "조건을 처음 만족한 날"이 아니라 "화면에서 처음 확인한 날"이다. 이 화면은 읽기 전용이 아니라 쓰기 트랜잭션이다.
- 저장은 `INSERT IGNORE`라서 화면을 동시에 두 번 열어도 중복 오류 없이 한 번만 저장된다.
- 배지 종류를 바꾸려면 `AchievementType`만 고친다. 코드 이름(`name()`)은 DB에 저장되므로 배포 후에는 바꾸지 않는다.

- **작성자 꾸밈**: 작품 게시판 카드·작품 상세(작성자·댓글·답글)·강사 게시판의 작성자에게 아래 세 가지가 보인다. **관리자 화면(관리자 게시판·관리자가 보는 작품 상세)에는 적용하지 않는다.**
  - 닉네임 색 → 닉네임 **글자색**이 바뀐다
  - 테두리 → **닉네임을 감싸는 둥근 테두리**(캐릭터 카드의 원형 테두리와 같은 팔레트)
  - 대표 배지 → 이름 오른쪽에 이모지(최대 3개, 마우스를 올리면 배지 이름)
- 닉네임 색·테두리는 **직접 장착한 경우에만** 입힌다. 장착한 적 없으면(기본값) 평범한 이름 — 모든 작성자에게 기본 테두리가 둘러지지 않게 한다. 탈퇴한 사용자에게는 입히지 않는다.
- `AuthorStyleService`(game 도메인)가 게시판 한 쪽의 작성자 전체를 **쿼리 3번**(장착 배지·꾸미기·취미 이름)으로 읽는다. work 도메인은 `WorkBoardService`가 이 서비스만 호출한다(GameService 를 부르지 않아 순환 의존을 피함). 작품 화면용 CSS 는 `static/css/author-badge.css`(접두사 `an-`/`ab-`).

## 5-1. 장착·해제는 새로고침 없이 (static/js/character.js)

- 대표 배지·꾸미기 장착/해제 폼(`<form data-ajax>`)은 스크립트가 가로채서 `fetch`로 보내고, 결과 문구를 **화면 아래 안내 창**에 띄운다. 성공하면 같은 주소를 다시 읽어 캐릭터 카드·배지·꾸미기 영역만 바꿔 끼운다(스크롤 위치 유지, 처음 받은 배지의 NEW 표시도 유지).
- 대표 배지 칸이 모두 찼을 때(`FULL`)는 주의색 안내 창으로 "대표 배지 3칸이 모두 찼어요. 다른 배지를 장착하려면 먼저 장착 중인 배지를 하나 해제해 주세요."를 6초간 보여 준다.
- 서버(`GameController`)는 같은 URL 에 **두 가지 핸들러**를 둔다. 요청 헤더 `X-Requested-With: XMLHttpRequest`가 있으면 JSON `{success, message}`, 없으면 기존처럼 redirect + flash 안내. 그래서 스크립트가 꺼져 있어도 똑같이 동작하고, 안내 문구는 한 곳(`badgeEquipResult` 등)에서 만든다.
- 최종 판단은 항상 서버가 한다(가진 배지인지·해금됐는지·칸이 남았는지·CSRF 토큰). 스크립트는 화면만 갱신한다.
- 퀘스트 보상 받기는 아직 기존 방식(redirect)이다.

## 6. 한계·후속 아이디어

- 캐릭터 아이콘(동물 이미지)은 내 캐릭터 화면에서만 보인다. 작품 화면의 작성자 옆에도 보이게 하려면 `AuthorStyleService`에 아이콘 코드를 더하면 된다. 닉네임 색·테두리·대표 배지는 작성자 꾸밈으로 이미 보인다.
- 배지·퀘스트 보상 수령 알림은 넣지 않았다(`notifications`의 종류·대상 칼럼이 DB CHECK로 묶여 있어 종류 추가에 DB 변경이 필요).
- 퀘스트 동시 더블클릭은 기본키가 막지만, 그 경우 두 번째 요청은 오류 화면이 날 수 있다(확인 후 저장이라 드묾).
- 테스트: `GameRulesTest`(단위), `GameServiceTest`(로컬 DB 통합).

## 5-2. 보스 대치 화면 (취미별 보스 + 행동별 연출 + 격파 보상)

내 캐릭터 화면 **보스전 목록 바로 위** `#gm-battle` 카드. 수강 중인 강의마다 탭이 하나씩 있고, 탭을 누르면 그 강의의 보스 대치(체력·지금 할 일·보상)가 페이지 이동 없이 열린다. 처음에는 가장 급한 한 건(반려 > 판정 대기 > 보스의 방 열림 > 수련 중 > 격파 > 기간 끝)이 열려 있고, 연출은 탭을 처음 열 때 재생된다.

꾸미기는 동물·대표 취미 의상·머리 장식(마스터의 왕관)을 따로 고른다. 보스 대치·격파 보상에도 선택한 동물 + 해당 강의 취미 의상 + 장착한 왕관이 나온다. (`user_avatars.outfit_code/head_code` — 기존 DB는 `migration_game_crown.sql` 한 번 실행)

| 취미 | 보스 | 일반 공격(차시 완료) | 필살기(최종 과제 제출) |
|---|---|---|---|
| 색연필화 | 색을 훔친 먹구름 | 🖍️ 색연필 빛줄기 | 🌈 무지개 채색 |
| 디지털 드로잉 | 오류 난 픽셀 골렘 | 🖊️ 스타일러스 궤적 | 💥 레이어 폭발 |
| 디저트 만들기 | 폭주한 반죽 슬라임 | 🌫️ 밀가루 구름 | 🍰 달콤한 피니시 |

- 입문·중급·고급은 같은 보스에 장식(중급 뿔, 고급 뿔+왕관)과 크기만 더한다. 그림은 코드로 그린 SVG(`templates/game/boss-art.html`)라 이미지 파일이 없다.
- 단계(phase)와 지금 할 일: 수련 중 [이어서 수련하기] / 보스의 방 열림 [최종 과제로 도전] / 판정 대기(방어막) [강사 판정 대기]는 비활성 + [제출한 과제 확인] / 반려 [피드백 확인하기] + [재도전하기] / 수료 [강사 피드백 보기].
- 보스 체력은 **학습 진행도에 따른 연출 값**이다(차시를 끝낼 때마다 100 → 40, 판정 대기 40, 반려 55, 수료 0). 실제 평가 점수가 아니라고 화면에 안내한다.
- 연출(`static/js/boss-battle.js`): 지난번 본 상태를 브라우저(localStorage `nb-boss-{수강 id}`)에 기억해 달라진 것만 한 번 보여 준다. 차시 완료=공격, 제출=필살기, 반려=보스 반격, 수료 승인 후 처음 접속=보스 격파 + 보상 상자. 상자를 누르면 획득 경험치·수료 배지·새 직업 단계(이미지)가 펼쳐지고, 이후에는 "격파 완료" 카드와 [보상 보기]만 남는다. 모션 줄이기 설정이면 움직임 없이 결과만 보여 준다.
- 한계: "처음 접속"의 기억은 서버가 아니라 브라우저에 있다. 다른 브라우저·기기에서는 격파 연출을 한 번 더 볼 수 있다.
- 코드: `BossType`(정책) · `BossDTO` · `GameService.toBoss` · `boss-battle.css/js` · `BossBattleTest`
