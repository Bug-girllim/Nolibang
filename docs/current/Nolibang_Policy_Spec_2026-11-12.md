# 놀이방 LMS · 최종 정책 명세서

2026-11-12. [11월 5일 정책][policy]과 [구현 변경 기록][changes]을 현재 Service 구현과 대조해 역할별 운영 규칙과 예외를 정리한다. 각 규칙은 **구현 상태**와 **정책 확정 상태**를 따로 적는다. DB 제약은 [최종 DB 설계서][db-design], 변경 배경은 [DB·정책 변경 정리][change]에 있다.

**정책 상태 표기**

| 표기 | 의미 |
| --- | --- |
| 확정 | 기획 문서에 팀 결정(D-번호 등)으로 기록됨 |
| 11-06 결정 | `schema.sql`·코드 주석에 11-06 팀 결정으로 기록됨. 기획안 본문은 아직 개정되지 않음 |
| 확인 필요 | 구현은 되어 있으나 팀 결정 기록이 없거나, 변경 기록에 팀 확인 항목으로 남아 있음 |
| 미정 | 정책이 정해지지 않아 구현하지 않음 |

## 1. 역할별 요약

| 역할 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- |
| 비회원 | 메인 홈, 취미 탐색, 세부 취미·강의 상세 소개 | 수강 신청, 영상, 작품 게시판, 댓글·좋아요 |
| 학습자 | 수강 신청·대기·취소, 영상 학습, 최종 과제 제출·수정·재제출, 일반 작품 등록·삭제, 댓글·좋아요, 1:1 문의, 성장 기록, 회원 탈퇴 | 다른 학습자 기록 조회, 같은 강의 재신청 |
| 강사 | 현재 담당 분반 학습자 조회, 최종 과제 평가(시작·취소·초안·승인·반려), 취미 권한이 있는 작품의 댓글, 문의 답변 | 다른 강사 분반 조회, 학습자에게 일방 알림 발송, 강의 생성·정원 설정 |
| 관리자 | 강사 계정 발급·비활성화, 취미 권한, 분반 생성·담당·정원, 대기열 조회·취소, 공개 작품 숨김·복구, 통계 | 최종 과제 평가, 댓글 작성, 작품 직접 삭제 |

D-59는 카테고리·강의를 시드 데이터로 두기로 했지만, 현재는 관리자의 대분류·세부 취미·강의 편집과 영상 업로드도 구현돼 있다. 이 확대 범위의 MVP 포함 여부는 확인 필요다(CH-01·CH-03).

## 2. 수강·대기

| 규칙 | 현재 구현 | 정책 상태 |
| --- | --- | --- |
| 신청 자격 | 운영 중 취미의 공개 강의, 같은 강의의 수강·대기 기록 없음, 담당 강사가 있는 분반 1개 이상 | 확정 D-52·D-55 |
| 분반 배정 | 대기자가 있으면 빈자리가 있어도 대기열 끝. 없으면 담당 강사가 있는 분반 중 남은 자리가 가장 큰 분반, 같으면 분반 번호순 | 확정 D-52 |
| 정원 | 분반별 1~30, ACTIVE 수강만 센다. 정원은 현재 ACTIVE 수보다 줄일 수 없다 | 확정 D-52·D-53 |
| 대기열 | 강의별 단일 FIFO. 자리가 생기면 같은 트랜잭션에서 1순위부터 즉시 수강 확정하고 사이트 알림을 보낸다. 초대·수락 단계 없음 | 확정 D-53·D-57 |
| 자리가 생기는 경우 | 수강 취소, 수료 승인, 기간 만료, 만료 후 반려, 정원 증가, 담당 강사 지정 | 확정 §4-2 |
| 대기 취소 | 본인 취소 시 순번 소멸, 다시 대기하면 마지막 순번 | 확정 §4-3 |
| 관리자 대기 취소 | 관리자가 대기 중 항목을 취소할 수 있다 | 확인 필요 — D-59는 "조회만", CH-02 |
| 수강 취소 | 평가 대기·진행 중이면 거부. 그 밖의 ACTIVE 수강은 취소 → 자리 반환 → 대기 1순위 확정 | 확정 D-54 |
| 재신청 | 수료·취소·만료한 강의는 다시 신청·대기할 수 없다. DB UNIQUE (`user_id`, `course_id`)로도 막는다 | 확정 D-35·D-55 |
| 수강 기간 | 확정 시각부터 30일. 기간이 지나도 기간 내 제출한 과제가 평가 대기·진행 중이면 정원을 계속 점유하고, 평가가 끝나야 반환한다 | 확정 §4-2·§4-4 |
| 영상 접근 | 기간 안의 ACTIVE 수강 또는 수료자. 미수료 만료자는 차단 | 확정 D-42 |
| 차시 완료 | 서버가 관측한 실제 재생 시간이 영상 길이의 60% 이상 | 확정 §4-1 |
| 강사 교체 | 분반 담당 강사만 바꾼다. 학습자 분반 이동 없음. 평가 대기·초안·잠금·마감은 새 담당자가 승계 | 확정 D-59 |
| 강사 비활성화 | 담당 분반이 있으면 거부. 긴급 처리 시 즉시 비활성화하고 해당 분반을 담당 공백으로 바꾼다 | 확인 필요 — 긴급 처리 방식은 기획 문서에 없음 |

## 3. 평가·수료

| 규칙 | 현재 구현 | 정책 상태 |
| --- | --- | --- |
| 제출 조건 | 3차시 모두 완료, 기간 안의 ACTIVE 수강, JPG·PNG·WebP 1~5장(장당 50MB). 한 장이라도 실패하면 전체 롤백 | 확정 §5-0 |
| 제출 결과 | 평가 대기(WAITING). 마감 = 제출 + 7일. 제출만으로는 수료하지 않는다 | 확정 §5-0·§7-1 |
| 평가 전 수정 | 평가 시작 전·기간 안에서 같은 버전을 수정. 새 회차·새 마감 없음 | 확정 §5-0 |
| 평가 시작 | 현재 담당 강사가 시작하면 IN_REVIEW, 학습자 수정 잠금. 단순 열람은 잠금 아님 | 확정 D-56 |
| 시작 취소 | 피드백 초안이 비어 있을 때만 WAITING 복귀. 마감 유지 | 확정 D-56 |
| 수료 승인 | 공식 피드백 50자 이상(앞뒤 공백 제외). 한 트랜잭션에서 회차 승인 → 수강 COMPLETED → 자리 반환 → 승인·수료 알림 | 확정 §6·§7-1 |
| 반려 | 반려 사유 50자 이상. 기간 안이면 ACTIVE 유지로 재제출 가능, 기간이 지났으면 수강 EXPIRED·자리 반환 | 사유 필수는 확정 D-47. **50자 수치는 확인 필요**(§13 남은 미정) |
| 재제출 | 반려 후 정식 재제출 시 새 버전·새 회차·새 7일 마감. 횟수 제한 없음. 기간 안에서만 | 확정 §5-0 |
| 동시 평가 제한 | 수강 건당 평가 대기·진행 1건, 승인 1건(DB 생성 열 UNIQUE) | 확정 §5-0 |
| 마감 경고 | 강사 평가 목록에 마감 임박(48시간 이하)·기한 초과 표시. 알림은 보내지 않는다 | 확정 D-56, 알림 제외는 11-06 결정 |
| 평가 의무 | 수강 기간이 지나도 기간 내 제출한 과제는 끝까지 평가 | 확정 §7-1 |
| 결과 정정 | 승인·반려 확정 후 정정 기능 없음 | 확정 D-37(확장 이관) |
| 수준·마스터 배지 | 취미·수준별 수료 1건 이상이면 수준 배지, 같은 취미 3개 수준이면 마스터. 수강 기록에서 계산 | 확정 §6 |
| 승인 과제 수정·삭제 | 기능 없음. 수료를 자동 철회하지 않는다 | 미정 §6 |

## 4. 약관

| 규칙 | 현재 구현 | 정책 상태 |
| --- | --- | --- |
| 약관·만 14세 동의 | 가입 화면과 강사 첫 로그인(C-08)에 동의 단계 없음. `terms_agreements` 테이블 제외 | 11-06 결정. 기획 차이 승인과 개인정보·연령 정책 검토는 확인 필요(CH-06) |

| 동시 로그인 | 계정당 세션 1개, 새 로그인이 기존 세션을 끊는다 | 확정 §2. 세션 저장 방식(메모리)은 11-06 결정 |

## 5. 회원 탈퇴

| 규칙 | 현재 구현 | 정책 상태 |
| --- | --- | --- |
| 대상과 본인 확인 | 학습자만, 현재 비밀번호 확인. 강사·관리자 계정은 관리자가 관리 | 확정 §9 |
| 진행 중 수강 | 대기를 모두 취소한 뒤 ACTIVE 수강이 있으면 탈퇴 거부(대기 취소도 롤백) | 확인 필요 — 기획 문서에 차단 규칙 없음 |
| 학습 데이터 | 알림, 1:1 문의, 본인 작품·최종 과제(이미지 포함), 평가·공식 피드백, 진도, 대기, 수강(수료·배지), 성장 기록을 삭제 | 확정 §9 |
| 타인 작품 댓글 | 계정 식별값·이메일·전화번호·URL·외부 계정 패턴을 마스킹한 뒤 작성자 연결 해제. 자발 삭제 댓글과 타인 답글은 유지 | 확정 D-25. 자동 탐지가 모든 개인정보를 잡는다고 보장하지 않음 |
| 좋아요 | 사용자별 행 삭제, 개수만 `anonymous_like_count`에 합산 | 확정 §9 |
| 계정 | `WITHDRAWN`·`withdrawn_at` 기록, 아이디·닉네임·실명·이메일 익명화, 비밀번호 무효화, 인증 토큰 삭제, 모든 세션 종료 | 확정 §9 |
| 재가입 제한 | 이메일 원문 대신 HMAC-SHA256 확인값을 30일 보관, 만료 행은 스케줄러가 정리 | 확정 D-07 |
| 처리 단위 | DB 정리는 한 트랜잭션. 이미지 파일은 커밋 후 삭제, 실패하면 재처리 대상 | 구현됨 |
| 기능 범위 | 위 탈퇴 기능 전체 | 확인 필요 — MVP 포함·기록 보존 정책(CH-04) |

## 6. 작품 삭제·숨김

| 규칙 | 현재 구현 | 정책 상태 |
| --- | --- | --- |
| 일반 작품 삭제 | 작성자 본인, `GENERAL`만. `deleted_at` 설정, 표시 버전·참고 피드백 연결 해제, 댓글·답글 `DELETED`, 회원 좋아요 행 삭제. 버전·이미지 행과 파일은 보존 | 삭제 기능은 D-32. 보존 범위는 확인 필요(CH-05) |
| 삭제 후 영구 정리 | 버전·이미지 파일의 영구 정리 시점 없음 | 미정 |
| 최종 과제 직접 삭제 | 기능 없음 | 미정 §5-0·§6 |
| 관리자 숨김 | 공개 작품만. 사유 필수(현재 최소 5자·최대 1000자), 이력 기록, 작성자에게 숨김 알림 | 확정 Q-01·Q-02. **사유 최소 5자는 임시값** |
| 숨김 중 접근 | 일반 이용자는 목록·상세·이미지 URL 차단. 작성자·현재 담당 강사·관리자는 열람. 수료·배지·평가 의무 유지 | 확정 Q-01·Q-02 |
| 복구 | 숨김 상태만 복구. 사유 선택(비우면 기본 문구), 작성자에게 복구 알림. 작성자가 비공개로 바꿨다면 공개되지 않음 | 확정 Q-01 |
| 관리자 조치 범위 | 댓글 개별 조치·작품 직접 삭제 없음. 조치 결과는 사이트 알림과 작성자 사유 화면으로만 전달 | 확정 §8·D-57 |
| 신고 | 구현하지 않음 | 확장 D-33 |

## 7. 성장 시스템

| 규칙 | 현재 구현 | 정책 상태 |
| --- | --- | --- |
| 일반 작품 수준 태그 | 해당 취미의 최고 수료 배지 수준 이하만. 배지가 없으면 입문만. 저장 시 서버가 다시 검사 | 확정 §5-1 |
| 댓글 자격 | 학습자는 작품 수준 이상의 배지 필요, 취미 권한 강사는 가능, 작품 작성자는 배지와 무관하게 답글 가능, 관리자는 댓글을 쓰지 않음. 답글은 1단계 | 확정 §5-1·§8 |
| 참고 공식 피드백 | 같은 취미의 본인 최근 확정 평가(승인·반려) 1건만 연결 | 확정 D-17·D-47 |
| 경험치·레벨 | 저장하지 않고 기록에서 계산. 차시 30, 과제 제출 50, 수료 100+100×수준, 공개 일반 작품 40, 댓글 5(최대 20개), 받은 좋아요 3(최대 100개), 퀘스트 10~80. 최대 레벨 50 | 확인 필요 — 기획 문서에 없는 추가 기능 |
| 퀘스트 | 일일 3개·주간 4개. 같은 기간 중복 수령은 DB PK로 방지 | 확인 필요 |
| 업적·대표 배지 | 업적 15종, 캐릭터 화면을 열 때 달성 여부를 계산해 기록. 대표 배지는 업적·수료 배지 중 최대 3개, 장착 시 소유 여부를 서버가 검사 | 확인 필요 |
| 꾸미기 | 레벨·마스터 배지로 해금, 장착 시 서버가 해금 여부 재검사. 작품 게시판 작성자 표시에 반영(관리자 화면 제외) | 확인 필요 |
| 길드 | 분반 = 길드, 담당 강사 = 길드마스터, 순위는 해당 분반에서 쌓은 기여 경험치 | 확인 필요 |
| 성장 알림 | 배지·퀘스트 알림 없음 | 구현 선택(알림 종류 CHECK 변경 필요) |

RPG 요소는 `game` 도메인으로 추가됐으며, [구현 문서][game]에 도메인 추가에 대한 팀 합의가 필요하다고 기록돼 있다.

## 8. 남은 확인 사항

- 기획안 본문에 11-06 결정(약관 제외, 마감 임박 알림 제외, 메모리 세션)을 반영할지
- 관리자 대기 취소, 탈퇴 차단 조건, 긴급 강사 비활성화, 일반 작품 삭제 보존 범위의 공식 채택 여부
- 반려 사유 최소 50자, 숨김 사유 최소 5자 수치 확정
