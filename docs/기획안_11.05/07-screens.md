## 1. 화면 전반 정책

- 최초 로그인 사용자는 **취미 탐색**으로, 이후 로그인은 **메인 홈**으로 이동한다. 가입 완료 직후는 로그인 화면으로 이동.
- 운영 중/준비 중/비공개 카테고리는 **사용자에게 보여주는 범위가 다르다**.
- 본인 학습 현황은 비공개, 공개 프로필 **배지는 공개**, 작품 기록은 기본 비공개/선택 공개.
- 공식 평가 결과(승인/반려)·피드백, **대기→자동 수강 확정**, 수료, 댓글/1:1 질문 알림은 **우측 상단 알림함(사이트 알림)**으로만 보낸다. **이메일 알림은 없다**(D-57). 관리자 공개 작품 숨김·복구 사유는 작성자에게 사이트 안내. 신고 통지/화면은 확장, 관리자 과제 무효에 의한 수료 철회·유예/복구 통지/화면은 폐기.
- 한 계정 한 기기, 마지막 활동 후 1시간 로그인 만료, 영상 학습 중 제한적인 로그인 연장, 브라우저 종료 후 재로그인. 세션 만료로 로그아웃되면 홈 이동.
- **강의당 3차시 각각 60% 완료** 후에도 자동 이동 없음. 사용자가 직접 최종 실습 선택. **제출 후 수료가 아니라 강사 평가 대기**.
- 공통 강사 과부하·공백의 지연 안내는 관리자가 **분반 담당 강사 변경**(D-59)으로 해소하고, 영향 학습자 안내는 관리자가 서비스 밖 운영용 이메일로 수동 안내(Q-03a 방식 A, 시스템 메일 알림 아님)한다. 별도 이메일 발송 버튼·자동 감지 화면은 MVP에 추가하지 않는다.
- 수료용 최종 과제, 일반 작품, 공식 강사 피드백, 일반 댓글을 **화면상 구분**.

## 7. 주요 이동 흐름 (PC 웹)

### 학습자 정상

`회원가입·인증 → 로그인 → 취미·수준/공통 강의(3차시) 선택 → [빈자리] 분반 자동 배정·수강 확정 / [만석] 강의별 대기(FIFO) → 자리가 나면 1순위 자동 수강 확정·사이트 알림 → 30일 시작 → 3차시 각각 영상 60% 완료 → 최종 과제 제출 → 평가 대기 → 담당 강사 평가 시작(잠금) → 필수 피드백+수료 승인 → 수료·배지 → 영상 무제한 다시 보기·알림함`

### 반려·재신청 불가

`과제 반려(사유 확인) → [30일 안] 수정·정식 재제출(새 7일 평가 마감) / [30일 만료] 해당 회차 재제출 불가 → **같은 강의 재신청 불가**(D-55)` (수료한 강의도 재수강 불가, 다른 강의는 신청 가능)

### 공통 강사 운영

`강사 로그인 → 담당 분반 목록 → 수강생 진도·남은 기간 → 평가 대기/진행/완료 → 평가 시작 클릭(수정 잠금) → 피드백 초안 → 수료 승인/반려 → 강사 통계(P0, 분반별 현재 숫자)`

### 관리자 운영

`관리자 홈 → 강사 계정 생성(임시 비밀번호) → 공통 강의 분반 생성·담당·정원 지정 → 강의별 대기열 조회 → 강사 통계(P0) → 필요 시 분반 담당 강사 변경(미완료 피드백 초안·마감 유지) → 공개 작품 숨김·복구(P1)`

## 8. 화면 설계 단계에서만 결정할 상세

- 화면 합치기/탭 분리, 메뉴·URL, 카드/테이블 UI 및 PC 화면 폭.
- 게시판 필터/정렬 UI 배치(기준값은 05 §8 D-09), 알림 표시 우선순위, 로딩·빈 상태, 대용량 이미지 진행률.
- 버튼 정책: **관리자 숨김은 작성자가 수정해도 해제되지 않고, 복구는 관리자만 가능**. 작성자 본인 삭제는 D-32에 따라 별도 확인한다. 일반 작품 수준 태그는 현재 배지에 맞는 선택지만 노출한다. 신고 중 수정 잠금은 확장 D-33으로 MVP 미구현.
- **[MVP 선정 회의 제안·표시 원칙]** 현재 MVP 범위에서 제외한 기능은 사용 가능한 것처럼 보이는 메뉴·버튼으로 시연하지 않는다. 숨김 또는 ‘준비 중’ 표기는 화면 설계에서 결정한다(참조: `DEV_REVIEW.md` §3-2). 기존 기능·정책·우선순위는 변경하지 않는다.
- **미포함:** 신고 접수·처리 화면(D-33), 준강사 실제 화면, 챌린지·성장 코인·광고 관리·유료 강의 결제 화면, 자동 생성 작품집 등은 후속 확장.

> **화면 정책:** 화면에서 보이는 버튼 상태와 관계없이 실제 이용 권한·수정 가능 여부가 우선한다. 이를 강제하는 구체적 방법은 `DEV_REVIEW.md`에서 검토한다.
