> **[2026-11-05 MVP 단순화 결정 D-51~D-59 · 이 문서의 모든 앞선 기준보다 우선]** ① 강사 계정은 관리자가 **임시 비밀번호로 즉시 생성**(메일 설정 링크 없음, 첫 로그인 시 비밀번호 변경, D-51·FR-012) ② 공통 강의 분반은 여러 개·정원 1~30 유지, 배정은 **남은 자리가 가장 큰 분반** 한 줄 규칙, **강사 합산 30건 검사 삭제**(D-52·FR-052) ③ **단일 대기열(FIFO)** 유지, 자리가 나면 **1순위를 즉시 수강 확정 + 사이트 알림**, 초대·수락·48시간 단계 없음(D-53·FR-053) ④ 수강 취소 → 자리 반환 → **대기 1순위 자동 확정**(D-54·E6) ⑤ 같은 강의는 **수료(D-35)뿐 아니라 취소·만료한 강의도 이번에는 재신청 불가**(D-55·FR-055 P1) — 재수강 기록 삭제(D-36)·이전 시도 보관(D-44·FR-056)은 대상이 없어 보류 ⑥ 평가는 **시작(잠금) → 초안 → 승인/반려**, 시작 취소, 마감 임박·기한 초과 경고 유지(D-56·FR-023·030·031) ⑦ 알림은 **사이트 알림만**: 평가 결과(승인/반려)·대기→자동 확정·수료, **이메일 알림 없음**(D-57·FR-035) ⑧ 강사 통계는 **현재 숫자만**: 분반별 수강 중·수료·반려·평가 대기 수(D-58·FR-051) ⑨ 관리자 MVP는 **강사 계정·분반(생성·담당·정원)·대기열 조회·관리자 홈**, 카테고리·강의는 **시드 데이터**(D-59). 결정 상세는 `05-policy.md` §14. 아래 본문에 남은 48시간 초대·합산 30건·재수강 회차·월별 통계 문구는 **결정 이력**으로만 본다.

## 1. 이 파일의 역할

이 파일은 개발 명령어와 세부 구현 이슈를 모으는 곳이 아니다. **왜 이 서비스를 만드는지와 MVP 이후 어떤 순서로 발전시킬지(확장·챌린지·수익화 로드맵)**를 추적한다. [확정 D-11] **MVP 구현 요구사항·우선순위(P0/P1/P2)·완료 조건의 정본은 [03](03-requirements.md)**, 서비스 정책·권한의 정본은 [05](05-policy.md)다. 아래 §2는 범위 요약이며 상충 시 03이 우선한다. 구체적인 문제 정의는 [01](01-problem.md), 역할별 시나리오는 [02](02-workflow.md), 구현 요구는 [03](03-requirements.md), 세부 기능은 [04](04-features.md), 운영 규칙은 [05](05-policy.md)에 둔다.

### 방향

- **[임시 확정 슬로건]** “강의를 보는 곳이 아니라, 취미 실력이 쌓이는 LMS.” 추후 수정할 수 있다.
- **[확정 서비스 방향]** 취미별 입문·중급·고급 강의, 유효 작품 실습, 점수 없는 피드백, 수료·배지, 선택적 성장 기록을 연결한다.
- **[확정 비교 원칙]** CLASS101·Skillshare·Domestika에도 프로젝트/갤러리/경로 등이 존재하며, Moodle·Canvas에도 강력한 학습·성과 관리 기능이 있다. ‘업계 최초’ 또는 ‘경쟁사에는 없다’고 주장하지 않는다.

### 1-1. 2026-10-30 PDF 최종 결정 반영·과거 기록 해석

- **최종 정책 PDF(9쪽)의 동일 항목은 이전 P-xx/D-xx보다 우선**한다. 기존 결정 이력은 **정책이 바뀐 과정을 기록하는 역사**이지, 폐기된 기능을 새로 구현하라는 뜻이 아니다.
- **중요 대체:** 1강의 1차시/9영상 확정 문구→**1강의 3차시·초기 9강의 총 27차시**, 제출 자동 수료→**담당 전문강사 필수 피드백·수료 승인 후 수료**, 1강의 1강사→**공통 강의의 여러 분반·분반별 1강사**, 신청 즉시 등록·수강 취소 불가→**정원·대기·48시간 초대·조건부 취소·수강 30일**.
- **폐기:** 과제 무효로 인한 수료 철회·배지 14일/30일 유예·철회 후 30일 재수료 보완·자동 수료. 구 FR-037~039·D-16/D-32의 해당 결과는 현행 기능이 아니다.
- **P등급 변경 이력:** 10-30 통합에서는 강사 통계 P1→P0(신규 FR-051)만 변경했다. **10-31 팀 결정(D-34)**으로 분반 자동 배정·정원(FR-052)·단일 대기열·48시간 초대(FR-053)·30일 수강기간(FR-054)은 **P0**, 재신청 제한·재수강(FR-055)은 **P1**로 지정했다. **11-05 단순화(D-51~D-59)**는 P등급을 바꾸지 않고 규칙만 줄였다(FR-053은 자동 확정, FR-055는 재신청 불가). FR-011·014는 시드 데이터로 범위 제외, FR-056 보류. 그 밖에 등급이 없는 사항에는 임의 P0를 부여하지 않는다. 신고·준강사는 [확장], **개인 제작 강의는 기능 전체가 [확장](D-45)**.
- **미결정** PDF 09장 U01~U12 및 추가 예외는 `05-policy.md` §11-1에 현행 질문지로 등록했다. 과거 `남은 미정 없음` 주장은 해당 날짜의 판단 이력으로만 본다.

### 2-1. MVP 내부 우선순위 — 03으로 일원화 [확정 D-11]

- 등급 정의: **P0** 없으면 시연 불가 / **P1** 차별성·핵심 정책 시연 / **P2** 시간이 남으면 구현(미구현이어도 정책은 유지).

- 03의 P0/P1/P2는 **기획상 우선순위**이며 실제 구현 범위는 개발 설계 및 검증 결과로 구분한다. 기존 기능을 근거 없이 범위에서 제외하지 않는다.
- 이전 이 절의 등급 표와 03이 달랐던 항목은 03 기준으로 정리했다: 카테고리 삭제·복구 **P1**(FR-011), 나의 학습 현황 **P0**(FR-029 신설), 공식 피드백 신고 **P2**(FR-047 신설), 공개 프로필 **P2**(FR-048 신설).

## 3. MVP에서 제외하거나 별도 승인해야 할 것

- **[확장]** 준강사 신청·심사·승인·보조 기능. 이번에는 역할/메뉴 구조만 기록한다. **준강사는 학습 질문 응답·실습 보조만 수행하며 공식 평가·피드백 인계 대상이 아니다(Q30·D-46).** 강사 담당 자격 정지 기간의 미평가 건은 MVP에서 **다른 적격 분반으로 수강 건 이동(D-40) 또는 관리자의 공백 대기 관리**로 처리한다.
- **[확장]** 관리자 강의·영상 등록 화면(MVP는 DB 입력 후 관리자 검수·승인, D-01), 강사 직접 강의·영상 업로드, 영상 주석형·음성형 피드백, 라이브 Q&A, 오프라인 클래스 예약, 쿠킹 모드, 계량 계산기, 작품집 PDF.
- **[확장 D-33 / 현행 범위 재확인]** 작품·댓글·공식 피드백·문의 신고와 신고 잠금·병합·보존 예외. **관리자 직권 과제 무효에 따른 수료 철회·14일 배지 유예·무효 보완·오판 복구·무효 자료 30일 보관은 2026-10-30 폐기**한다. **MVP는 공개 작품 숨김·복구만 제공**한다(Q-01/Q-02).
- **[확장]** 학습자 정식 이의제기/재검토 신청, **강사의 반려→승인 오반려 정정(D-37)**. **[폐기]** 관리자 무효→수료 철회에 종속된 내부 오판 복구.

- **[확장]** 모든 수익화 기능(광고·유료 강의·준비물 제휴·코인) 및 챌린지 기능은 이번 MVP에서 제외한다.

## 4. ★ 최우선 기능 확장 — 챌린지·가벼운 게임화

**[우선순위 확정] MVP 완료 뒤 가장 먼저 추진할 확장**

1. **7일 챌린지:** 예: 매일 한 장 드로잉. 참여·일별 실습·진행 상태.
2. **30일 챌린지:** 예: 30일 베이킹 성장일지. 이전과 이후의 결과물 확인.
3. **별도 완주 배지:** 기존 입문/중급/고급/마스터 배지와 구별. 챌린지 배지만으로 수료·댓글 권한·준강사 자격을 주지 않는다.
4. **기존 데이터 재활용:** 개인 성장 목록과 일반 작품/실습 일지를 연결한다. 공개 업로드를 강제하지 않는다.
5. **[확장 미정]** 연속 인증·결석·재참여·중복 인증·배지 취소·운영 권한 등 세부 기준.

**중요:** ‘최우선 **기능** 확장 = 챌린지’와 ‘최초 **수익화** 단계 = 배너 광고’는 서로 다른 로드맵이다.

### 10-5. 실제 확장 도입 때만 다룰 결정·검증 항목

- **기준값은 지금 정하지 않는다.** 과부하 건수, 등록 상한, 경고 예외, 지원 종료 기간, 저장 총량, 자동 지연 감지 임계값은 실사용 데이터와 팀 의사결정 뒤 확정한다.
- **2026-10-30 확정 정책이 우선한다.** 과제 수정·임시저장/강사 교체로 7일 기한을 재설정하지 않으며, 수료일은 **강사의 승인일**이다. 강의당 여러 **분반**을 운영하고 각 분반 담당자는 1명이며, 강사 통계는 **P0**이다. 영상 접근은 **수강 30일 이내 또는 수료자**(D-42)이며 구 60% 완료자 제공 종료 예외는 대체되었다. 10-31 등급 지정은 D-34를 따른다.
- **확장과 현행을 구분한다.** 신고·댓글 단독 제재·비공개 작품 조사·준강사 실제 보조 실행·강사 일방 자동 발송은 기존 확장 경계를 지킨다. **공통 강의별 단일 대기열(FIFO)·자동 확정은 확정된 운영 정책(D-53)**이므로 ‘기능 자체 MVP 제외’라고 쓰지 않는다. 관리자 무효→철회·유예는 확장이 아니라 폐기다.
- **정식 공개 전 필수 안전성 확인:** §11의 **출시 전 보안·운영 게이트**에 따라 신고 없는 커뮤니티의 악성 댓글·개인정보 노출 대응과 인증·인가·파일 업로드 등의 위험을 확인한다. §10의 [추천·확장] 기록 자체가 위험 해결이나 공개 승인이라는 뜻은 아니다.
- **도입 우선순위는 확정하지 않는다.** `§4`의 '7일·30일 챌린지 최우선 기능 확장' 결정과 `§5`의 수익화 순서는 유지한다. 실제 사고·안전/운영 문제 발생 시 팀이 확장 재우선순위를 별도 결정할 수 있다.
- **구현은 개발 설계에서 결정한다.** `00-backlog.md`에는 운영상 문제·후속 해결 목표를 기록하며, 기술 선택/DB/API·알림 발송 방식/수치 결정은 구현 착수 시 `DEV_REVIEW.md` 등의 검토를 거친다.

### 11-2. 정식 공개 승인 판단 기준

- **검토 시점:** 불특정 일반 사용자의 신규 회원가입·실제 학습·작품/댓글 공개를 허용하기 **전**. 팀 내부 시연·통제된 테스트는 별도의 제한 환경에서 수행할 수 있다.
- **기록 방식 [출시 준비 권장]:** 각 `PUB-SEC-xx` 항목에 대해 **담당자 / 검토 결과(충족·보완 필요·미검증) / 테스트·점검 근거 / 필요한 조치 / 재검토 결과**를 출시 전 별도로 기록한다. 이 백로그는 검사 목록이지 테스트 완료 증거가 아니다.
- **출시 판단:** 핵심 안전 조건이 미충족 또는 미검증인 경우 **정식 공개를 승인하지 않는다**. 먼저 보완·재검증하거나, 위험 기능을 제한하고 공개 범위를 조정한다. 조건 충족 여부는 실제 테스트·운영 준비 결과를 기준으로 판단한다.
- **책임 구분:** 기획 단계는 *보호해야 할 사용자 결과·출시 전 확인 조건*을 정한다. `DEV_REVIEW.md` 및 후속 개발 설계는 *보안 설정·테스트 방법·복구·운영 절차*를 결정한다. 특정 프레임워크/필드/기술 선택을 이 문서에서 확정하지 않는다.
- **현재 결정과의 관계:** 현행 결정의 **신고·제재·무효 MVP 제외**, Q-01·Q-02의 **공개 작품만 관리자 숨김·복구**, 공통 강의 분반당 담당 강사 1명, `03`의 P0/P1/P2는 **모두 그대로 유지**한다. `PUB-SEC`는 `FR-xxx`가 아니며 신규 MVP 기능 ID가 아니다. 정식 공개를 위해 신고/제재 등 기능 확장이 꼭 필요하다고 확인되면 **MVP 정책을 소급 변경하지 않고 별도 출시 준비·확장 결정**으로 관리한다.
- **로드맵 구분:** §4의 ‘7일·30일 챌린지 최우선 **기능 확장**’과 §5의 수익화 도입 순서는 변경하지 않는다. 단, **정식 공개를 위한 안전·법적·운영 필수 조치가 있으면 출시 전 먼저 충족**해야 하며, 이를 챌린지 등 선택적 기능 확장과 혼동하지 않는다.

### 11-3. 이번 검토에서 아직 확정되지 않은 것

- 일반 공개 개시일, 담당자 배정, 외부 문제 제보 창구의 실제 형태, 악성 댓글 처리 수단, 보안 테스트 결과, 개인정보 처리 안내의 최종 내용, 운영 장애 대응 매뉴얼은 **아직 확정·검증되지 않았다**.
- 이 항목들의 **검토 의무만 확정**한다. 새 신고/관리자 삭제/자동 감지/개별 알림 화면이 현재 구현되었다고 기록하지 않으며, 필요한 수단은 정식 공개 전에 별도 판단한다.
- 공개 불가 판정 시 제한 테스트 운영을 계속할 수는 있으나, 테스트 참여자의 개인정보·파일 접근·보관에도 필요한 보안 보호는 적용한다.

- **[D-32 현행 경계]** 일반 작품 작성자 삭제(P2)는 유지한다. **수료 승인된 최종 과제의 작성자 삭제→수료 철회는 폐기된 구 결정**이다. 승인 후 삭제의 허용 조건과 자료·배지 후처리는 미정이므로 현행 자동 처리로 구현하지 않는다.
