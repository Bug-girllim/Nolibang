> **화면 폴더 이름 = 도메인 이름**으로 맞춰, 컨트롤러가 `return "enrollment/apply";`처럼 반환하면 바로 찾을 수 있게 했다. HTML 파일은 `U-S05.dc.html` → `templates/enrollment/apply.html`처럼 **화면 ID 대신 의미 있는 이름**으로 옮긴다(화면 ID는 파일 상단 주석에 남김).

## 2. 패키지·주요 클래스 역할

### 2-1. 계층별 공통 규칙 (모든 도메인에 동일)

| 계층 | 하는 일 | 하지 않는 일 | 근거 |
|---|---|---|---|
| **controller** | URL 매핑, 파라미터·DTO 받기, `@Valid` 선언, 뷰 이름·`redirect:` 결정 | 비즈니스 규칙 판단, 트랜잭션, Entity 다루기, try-catch | 미니 프로젝트 MenuController |
| **service** | 흐름 조립(조회 → 규칙 확인 → 변경 → 저장 → DTO 변환), `@Transactional` | 화면 이름·Model 다루기, Entity를 Controller로 반환 | 미니 프로젝트 MenuService |
| **entity** | 테이블 매핑 + **자기 상태로 판단하는 규칙**(`ReviewRound.start()`, `Enrollment.cancel()` 등), `create()` 정적 팩토리 | public setter, Repository 주입, DTO 알기 | 미니 프로젝트 Menu, Security User |
| **policy** | **다른 행을 조회해야 판단되는 규칙**. 위반 시 `BusinessException`만 던짐 | 저장·상태 변경 | 미니 프로젝트 MenuNamePolicy |
| **dto** | 화면 ↔ 서비스 데이터 전달, 입력 형식 검증 어노테이션, `from(entity)` 변환 | DB 접근, 비즈니스 로직 | MenuDTO, LoginUserDTO |
| **repository** | `JpaRepository` 상속, 쿼리 메서드, `@Query` | DTO 변환, 규칙 판단 | MenuRepository |

| 클래스 | 역할 |
|---|---|
| `EnrollmentService.apply()` | ① `EnrollEligibilityPolicy`로 중복·재신청 불가 확인 ② 대기자가 있으면 대기열 끝으로 ③ 없으면 분반 행을 잠그고(`FOR UPDATE`) `SectionAssignPolicy`로 분반 선택 → `Enrollment.create()`(확정 시각, +30일) |

| `SectionAssignPolicy` | 담당 강사가 있는 분반 중 `정원 − 활성 수강`이 가장 큰 분반, 동률이면 분반 번호순(D-52) |

**review (P0 핵심)**

| 클래스 | 역할 |
|---|---|
| `ReviewRound` (entity) | 상태 전이 메서드를 엔티티가 가짐: `start(instructorId)`(WAITING만 가능, 수정 잠금) / `cancelStart()`(초안 비었을 때만) / `saveDraft()` / `approve(feedback)` / `reject(reason)` (50자 미만이면 예외). 마감 = 제출 시각 + 7×24시간, `isDueSoon(now)`(48시간 이하)·`isOverdue(now)` |
| `AssignmentService` | 최초 제출: `SubmissionPolicy` 확인 → 이미지 1~5장 모두 저장 성공 시에만 `Work(FINAL)` + `ReviewRound(WAITING)` 저장. 평가 전 수정(기한 불변), 반려 후 정식 재제출(새 `ReviewRound`, 새 7일) |
| `ReviewService` | 현재 분반 담당 강사인지 검사 → 엔티티 메서드 호출. 승인 시 `Enrollment` 수료 처리 + `SeatService.fillVacancies(courseId)` + 알림. 반려 시 알림(만료 후 반려면 자리 반환) |
| `BadgeService` | 수료한 수강 건을 취미·수준으로 묶어 배지 계산(10_TRACE: 저장하지 않고 계산). U-S13, U-S02 3칸 표시, `WorkLevelPolicy`, `CommentPolicy`에서 사용 |

**instructor / admin**: 자체 Entity 없이 다른 도메인의 Repository·Service를 조회해서 화면용 DTO로 조립한다. `InstructorStatService`는 `enrollments`·`review_rounds`를 분반별로 `GROUP BY` 집계하는 `@Query` 하나로 현재 숫자를 계산한다(D-58). 관리자 A-S13도 같은 서비스를 재사용한다.

## 4. 설계에 사용한 기술과 선택 이유

### 4-1. 배운 기술 🟢

| 기술 | 사용 위치 | 선택 이유 |
|---|---|---|
| Spring Boot + Gradle, Java 21 | 프로젝트 전체 | 미니 프로젝트·Security 과목과 같은 구성 (Boot 3.5.x) |
| `@Controller` + `ModelAndView` / `redirect:` | 모든 컨트롤러 | 화면 기반 구조. 등록·수정·삭제 후에는 redirect(Servlet 과목: 새로고침 중복 실행 방지) |
| `RedirectAttributes.addFlashAttribute` | 신청 완료·저장 완료 안내 | redirect 후 메시지 1회 표시(C-11 "토스트") |
| `@PathVariable` / `@RequestParam` / `@ModelAttribute` | 강의 id, 검색 조건, 폼 입력 | chap01~02 |
| `@ResponseBody` | 재생 시간 보고, 아이디·닉네임 중복 확인 | 화면 전체를 다시 그리지 않는 요청만 데이터로 응답(미니 프로젝트 `/menu/category` 방식) |
| Thymeleaf `th:fragment` | 공통 헤더·역할별 메뉴 | HTML 시안의 공통 헤더(학습자/강사/관리자 메뉴)를 조각으로 분리 |
| Spring Data JPA (`JpaRepository`, 쿼리 메서드, `@Query` native, `Sort`) | 모든 repository | `existsBy…`(중복 확인), `findBy…OrderBy…`, 통계 `GROUP BY`, 행 잠금 `FOR UPDATE` |
| `@Entity`, `@Enumerated(STRING)`, `@GeneratedValue(IDENTITY)`, `LocalDateTime` | 모든 entity | 상태값이 많아 enum을 STRING으로 저장(수업 권장). DB CHECK 값과 글자까지 같게 맞춤 |
| `@Transactional` + 변경 감지 | 모든 상태 변경 서비스 | 엔티티 메서드로 상태만 바꾸면 UPDATE 자동 실행. 예외 시 롤백 → "자리 반환 + 1순위 확정 + 알림"을 한 번에 처리 |
| Bean Validation (`@Valid`, `@NotBlank`, `@Size`, `@Min`, `@Positive`) | 입력 DTO | 형식 검증은 DTO, 상태 검증은 Entity·Policy (미니 프로젝트 원칙) |

| 생성자 주입 + Lombok `@RequiredArgsConstructor` | 모든 Bean | 수업 권장 방식 |
| 정적 팩토리 `create()` / `from()` | Entity 생성, Entity → DTO | Security·미니 프로젝트 방식(ModelMapper 미사용) |
| 인터페이스 계약 + Fake 구현체 | 팀원 간 도메인 경계에서 필요할 때 | 미니 프로젝트 `MenuOrderHistoryChecker` (§5 참고) |

### 5-2. 바꾼 부분

| 원래 규칙 | 변경 | 이유 |
|---|---|---|
| 실행 클래스를 `global/config`에 두고 `ContextConfig`(`@ComponentScan`), `JpaConfig`(`@EnableJpaRepositories`, `@EntityScan`)를 따로 둠 | **실행 클래스를 최상위 `com.wanted.lmspractice`에 두고 두 설정 클래스는 만들지 않음** | 최상위에 두면 하위 패키지를 자동 스캔한다. 설정 클래스 2개가 필요 없어져 구조가 단순해진다(수업 chap07 주석에서 설명한 원리 그대로) |
| `domain/x/model/{dao, dto, entity, policy, service}` (model 한 단계 더) | **`domain/x/{entity, repository, dto, service, policy}`** (model 제거) | 도메인이 12개라 폴더 깊이를 한 단계 줄이는 편이 찾기 쉽다. 역할 구분은 그대로 유지 |
| `dao` 패키지명 | **`repository`** | 수업에서 "JPA에서는 DAO == Repository로 인식하자"고 했고 클래스명도 `…Repository`라 일치시킴 |
| Security는 `domain/auth/config/SecurityConfig` | **`global/config/SecurityConfig`** | 보안 설정은 모든 도메인 URL에 적용되는 전역 설정이라 global이 자연스럽다. 인증 화면·핸들러·UserDetails는 `domain/auth`에 그대로 둠 |
| 다른 팀 데이터는 인터페이스 계약 + Fake로만 접근 | **같은 프로젝트 안에서는 서비스가 다른 도메인 서비스를 직접 호출하는 것을 허용**하고, 계약 방식은 **아직 구현되지 않은 남의 기능에 먼저 의존해야 할 때만** 쓴다 | 미니 프로젝트는 "Menu 팀 ↔ Order 팀"처럼 경계가 하나였지만, 이 프로젝트는 신청 → 학습 → 평가 → 수료가 한 흐름으로 이어져 모든 경계를 인터페이스로 만들면 클래스가 크게 늘어난다. 예: `ReviewService`(평가 담당 팀원)가 `SeatService`(수강 담당 팀원)를 써야 하는데 아직 없으면, 그때만 `SeatReleaser` 인터페이스 + Fake를 둔다 |
| Policy를 도메인마다 둠 | **규칙이 실제로 있는 도메인에만** policy 패키지를 만듦 (hobby·course·notification·inquiry·instructor·admin은 없음) | 불필요한 패키지를 만들지 않기 위해 |
| 화면 ID 그대로 파일명 | 템플릿은 의미 있는 이름(`enrollment/apply.html`) | 강의 상세 10개 변형 화면 등을 **템플릿 1개로 통합**하기 위해 |
| (규칙 없음) | `instructor`, `admin` 패키지는 **Entity 없이 Controller·Service·DTO만** | 강사 홈·관리자 홈·통계는 여러 도메인 데이터를 모아 보여 주는 화면이라 데이터 소유 도메인이 따로 없다 |
| Security 과목 `rememberMe` 사용 | **사용하지 않음** | 기획: "브라우저 종료 후 재접속하면 다시 로그인"(05 §2) |
| Security 과목 `csrf.disable()` | ❓ **팀 결정** | 수업은 학습용으로 끔. 수업 주석에 "세션 방식 운영 환경은 반드시 활성화"라고 적혀 있다. Thymeleaf `th:action`은 토큰을 자동으로 넣어 주므로 켜도 부담이 적다 |

## 8. JSP → Thymeleaf로 바꾸면서 달라지는 점 (11-06 추가)

| 자료의 JSP 관련 내용 | Thymeleaf에서 | 조치 |

## 9. 강의·카테고리 관리: 기존 기획 유지 (11-06 팀 결정)

- 카테고리·세부 취미·9강의·27차시·영상 경로는 **`sql/seed.sql`로만 입력**한다(D-59). 화면에서 생성·수정·삭제·검수하는 기능은 만들지 않는다.
- 영상 파일은 개발자가 업로드 폴더에 직접 넣고 시드 SQL에 경로·길이를 적는다. 영상 업로드 기능은 없고, 학습자 영상 재생(`learning.LessonVideoController`, 접근 권한 검사)은 그대로 필요하다.
- 강사 자격은 **취미 활동 권한(`InstructorHobbyGrant`) + 분반 담당 지정(`CourseSection.instructor`)** 두 가지만 쓴다.

| HTML | 내용 |

## 10. DB 스키마 반영 (11-06 확정)

### 10-1. 표 ↔ 엔티티 (20개, 모두 1:1)

| 도메인 | 표 → 엔티티 |
|---|---|
| user | `users` → `User`, `auth_tokens` → `AuthToken`, `instructor_hobby_grants` → `InstructorHobbyGrant` (복합키) |
| hobby | `categories` → `Category`, `hobbies` → `Hobby` |
| course | `courses` → `Course`, `lessons` → `Lesson` |
| enrollment | `course_sections` → `CourseSection`, `enrollments` → `Enrollment`, `waitlist_entries` → `WaitlistEntry` |
| learning | `lesson_progresses` → `LessonProgress` (복합키) |
| review | `review_rounds` → `ReviewRound` |
| work | `works` → `Work`, `work_versions` → `WorkVersion`, `work_files` → `WorkFile`, `work_comments` → `WorkComment`, `work_likes` → `WorkLike` (복합키) |
| notification | `notifications` → `Notification` |
| inquiry | `inquiry_threads` → `InquiryThread`, `inquiry_messages` → `InquiryMessage` |

- 다른 표를 가리키는 칼럼(`…_id`)은 **Long 값**으로만 둔다. 다른 도메인 엔티티를 직접 참조하지 않는 규칙(§2-1)과 같다. 같은 도메인 안에서 연관관계가 필요하면 담당자가 `@ManyToOne`으로 바꿔도 된다.
- `created_at`·`updated_at`은 DB가 기록(`insertable = false, updatable = false`).
- DB 생성 칼럼(`waitlist_entries.waiting_user_id`, `review_rounds.active_enrollment_id`·`approved_enrollment_id`)은 매핑하지 않는다.
- DB 기본값이 있는 NOT NULL 칼럼(상태값, `admin_hidden`, `played_sec` 등)은 필드 초기값으로 맞췄다.

### 10-3. 11-06 팀 결정으로 DB와 함께 정한 것

| 결정 | 설계 반영 |
|---|---|
| 약관·만 14세 확인 빼기 | 약관 표·엔티티 없음 |
| 피드백 마감 임박 알림 빼기 | `NotificationKind`에 없음. 평가 목록 화면 경고로만 표시 |
| 승인 과제 수정·삭제(D-63) 미정 | `WorkVersion`은 제출·평가 전 수정·재제출 버전 저장용으로만 사용. 승인 후 수정·삭제 기능은 만들지 않음 |
| 로그인 세션은 우리 설계 | Spring Session 표 없음. `maximumSessions(1)` + `session.timeout: 60m` |
| 관리자 로그인 직후 막히지 않게 | 시드 관리자 `must_change_password = FALSE`. 비밀번호 변경 강제(C-09)는 강사 전용 |
| 복합키·숫자 수준 | `@IdClass`, `AttributeConverter` 사용 (🟡, §4-2) |
