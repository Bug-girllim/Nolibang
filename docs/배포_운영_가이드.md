# 배포·운영 가이드 (시연 서버용)

- 작성일: 2026-11-11 · 기준 브랜치 `verify/security-deploy`
- 시연 서버는 **아직 정해지지 않았다.** 서버가 정해지면 이 문서 순서대로 띄우고, 맨 아래 「시연 서버 점검」을 그 주소에서 다시 한다.
- 비밀번호·키는 이 문서와 저장소에 적지 않는다. 모두 서버의 환경변수로만 넣는다.

## 1. 준비물

| 항목 | 내용 |
|---|---|
| Java | 21 (`build.gradle` toolchain) |
| DB | MySQL 8. 처음이면 `src/main/resources/sql/schema.sql` → `seed.sql` 적재 |
| 실행 파일 | `./gradlew bootJar` → `build/libs/lms-practice-0.0.1-SNAPSHOT.jar` |
| 업로드 폴더 | 서버의 고정 절대 경로(예: `/srv/nolibang/uploads`). 저장소의 `uploads/`(시드 이미지 `seed/`, 시연 영상 `videos/`)를 그대로 복사해 둔다 |

## 2. 환경변수

| 이름 | 필수 | 값 / 설명 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | ✅ | `prod` — 템플릿 캐시·응답 압축 켜기, SQL 콘솔 출력 끄기, 아래 `DB_*` 사용 |
| `DB_URL` | ✅ | `jdbc:mysql://호스트:3306/nolibang?characterEncoding=UTF-8&connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true` (원격 DB 가 TLS 를 요구하면 `&sslMode=REQUIRED`) |
| `DB_USERNAME`, `DB_PASSWORD` | ✅ | DB 계정 |
| `APP_BASE_URL` | ✅ | 사용자가 브라우저에 치는 주소 그대로(예: `https://nolibang.example.com`, LAN 시연이면 `http://192.168.x.x:8080`). **메일 인증·비밀번호 재설정 링크가 이 주소로 만들어진다** |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | ✅ | 발송용 Gmail 주소와 앱 비밀번호(2단계 인증 필요). 비우면 메일을 보내지 않고 링크를 서버 로그(WARN)에 남긴다 — 시연에서는 반드시 넣는다 |
| `UPLOAD_DIR` | ✅ | 업로드 폴더 절대 경로. 비우면 "실행한 폴더 기준 `./uploads`"라 실행 위치가 바뀌면 이전 업로드가 안 보인다 |
| `SESSION_COOKIE_SECURE` | HTTPS일 때 | `true` — 세션 쿠키를 HTTPS 에서만 보낸다. **HTTP 주소에서 켜면 로그인이 안 된다** |
| `WITHDRAWAL_EMAIL_HASH_KEY` | ✅ | 탈퇴 이메일 재가입 제한 확인값(HMAC)의 서버 키. 긴 임의 문자열로 정하고 **운영 중에는 바꾸지 않는다**(바꾸면 30일 제한 중인 이메일도 바로 가입된다). 비우면 개발용 기본 키를 쓴다 |
| `FORWARD_HEADERS_STRATEGY` | 프록시 뒤일 때 | `native` — nginx·Cloudflare·로드밸런서가 HTTPS 를 처리하고 앱은 HTTP 로 받을 때. 앱을 인터넷에 바로 열 때는 쓰지 않는다(헤더 위조) |
| `FILE_STORAGE`, `S3_*` | 선택 | 작품 이미지를 S3 호환 저장소에 둘 때(`application.yaml` 7번). 강사·관리자 업로드 영상은 S3 모드여도 `UPLOAD_DIR` 에 저장된다 |
| `LOGGING_FILE_NAME` | 권장 | 로그 파일 경로(예: `/srv/nolibang/logs/app.log`). 비우면 표준 출력에만 쓴다 |

## 3. 실행

```bash
java -jar lms-practice-0.0.1-SNAPSHOT.jar --server.port=8080
```

- 정상 기동: 로그에 `The following 1 profile is active: "prod"` 와 `Started LmsPracticeApplication` (점검 PC 기준 7~9초).
- 서버는 모든 네트워크 주소(0.0.0.0)에서 받는다. 다른 기기에서 접속하려면 **방화벽에서 포트를 연다.**
  - Windows: `netsh advfirewall firewall add rule name="nolibang" dir=in action=allow protocol=TCP localport=8080` (관리자 PowerShell)
  - Linux(ufw): `sudo ufw allow 8080/tcp`
- 상시 실행(Linux): systemd 서비스로 등록하면 서버 재부팅·앱 비정상 종료 후 자동으로 다시 뜬다.

```ini
# /etc/systemd/system/nolibang.service
[Unit]
Description=Nolibang LMS
After=network.target mysql.service

[Service]
User=nolibang
WorkingDirectory=/srv/nolibang
EnvironmentFile=/srv/nolibang/nolibang.env   # 위 환경변수(이 파일은 chmod 600, 저장소에 올리지 않는다)
ExecStart=/usr/bin/java -jar /srv/nolibang/lms-practice-0.0.1-SNAPSHOT.jar --server.port=8080
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

- **재시작하면 로그인 세션이 모두 끊긴다**(세션을 메모리에 둔다). 로그인 중이던 사람은 "세션이 만료되었습니다" 화면 → 다시 로그인하면 정상. 시연 직전에는 재시작하지 않는다.

## 4. HTTPS

- 권장 구성: 앞단(nginx·Caddy·Cloudflare)이 HTTPS 를 받고 앱(8080)은 HTTP 로 받는다.
- 앱 환경변수: `SESSION_COOKIE_SECURE=true`, `FORWARD_HEADERS_STRATEGY=native`, `APP_BASE_URL=https://…`
- 프록시는 `X-Forwarded-Proto`·`X-Forwarded-Host` 를 넘겨야 한다(nginx: `proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-Host $host;`). 업로드 영상 500MB 를 받으려면 nginx 에 `client_max_body_size 510m;`.
- 점검 결과(2026-11-11, 프록시 헤더를 흉내 낸 요청): 세션 쿠키 `Secure; HttpOnly; SameSite=Lax`, `Strict-Transport-Security` 헤더, 로그인 필요 화면 이동 주소가 `https://…` 로 만들어짐.

## 5. 백업·복원

DB 와 업로드 폴더는 **같은 시점**으로 묶어야 한다(DB 에 있는 이미지 행의 파일이 백업에 없으면 복원 후 그 이미지가 깨진다).

```bash
# 백업 — DB 를 먼저(한 순간의 스냅숏) 찍고, 그다음 업로드 파일을 묶는다
DB_URL=… DB_USERNAME=… DB_PASSWORD=… UPLOAD_DIR=/srv/nolibang/uploads BACKUP_DIR=/backup/nolibang ./scripts/backup.sh
# → /backup/nolibang/nolibang-YYYYMMDD-HHMMSS/{db.sql.gz, uploads.tar.gz, manifest.txt}, 최신 14개만 남김(BACKUP_KEEP)

# 매일 새벽 3시 (crontab -e)
0 3 * * * cd /srv/nolibang && set -a && . ./nolibang.env && set +a && ./scripts/backup.sh >> /backup/nolibang/backup.log 2>&1

# 복원 — 앱을 멈추고 실행, 끝나면 앱을 다시 띄운다
./scripts/restore.sh /backup/nolibang/nolibang-20261111-030000
```

- 백업 대상 파일: `UPLOAD_DIR/works/`(작품·과제 이미지), `UPLOAD_DIR/videos/uploaded/`(강사·관리자 업로드 영상). 시드 파일은 저장소에 있어 넣지 않는다.
- `BACKUP_DIR` 은 가능하면 서버와 다른 디스크·외부 저장소. 같은 디스크에만 두면 디스크 고장 때 함께 잃는다.
- 윈도우(Git Bash)에서는 `MYSQL_BIN="/c/Program Files/MySQL/MySQL Server 8.0/bin"` 를 함께 넣는다.
- 복원 연습(2026-11-11, 로컬 `nolibang`): 백업 → 같은 DB 에 복원 → 표 21개 행 수·주요 표 5개 체크섬 동일, 뷰 6·CHECK 53·FK 46 그대로, 이미지 파일 2개 복원 확인. 다른 DB 이름으로 복원하려면 `RESTORE_DB=<이름>`(그 DB 에 권한이 있어야 한다).

## 6. 시연 서버 점검 (서버가 정해지면 그 주소에서)

| # | 확인 | 방법 |
|---|---|---|
| 1 | 기동·프로필 | 로그에 `prod` 와 `Started`, ERROR 없음 |
| 2 | 외부 접속 | 다른 기기(휴대폰·다른 PC)에서 `APP_BASE_URL` 접속 → 홈 표시 |
| 3 | 로그인 유지 | 학습자·강사·관리자 로그인 → 화면 이동해도 로그인 유지(HTTPS 면 쿠키 `Secure` 확인) |
| 4 | 메일 링크 | 새 계정 가입 → 실제 메일 수신 → 링크가 `APP_BASE_URL` 주소인지, 다른 기기에서 눌러 인증되는지. 비밀번호 재설정 메일도 같은 방법 |
| 5 | 업로드·열람 | 작품 이미지 올리기 → 다른 계정으로 공개/비공개 열람 확인. 강사 영상 업로드 → 담당 강의 차시에 연결 → 학습자 재생 |
| 6 | 재시작 | 앱 재시작 → 업로드한 이미지·영상이 그대로 보이는지(`UPLOAD_DIR` 고정 확인), 다시 로그인 |
| 7 | 백업 | `backup.sh` 1회 실행 → `manifest.txt` 의 파일 수 확인. 가능하면 연습용 DB 에 `RESTORE_DB` 로 복원 |
| 8 | 로그 | `LOGGING_FILE_NAME` 파일에 로그가 쌓이는지, 비밀번호·토큰이 찍히지 않는지(메일 계정을 넣었으면 인증 링크가 로그에 남지 않는다) |
